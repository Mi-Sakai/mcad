# リリース手順

mcad のリリースは「実装を止めて、バージョン番号とドキュメントを一斉に整合させる」
作業。コードは原則変更しない(v0.5.0 のように実装が混ざった例外はあるが、
以後は分けている)。

## 0. 前提の確認

着手前に以下がすべて済んでいること。済んでいなければリリースに入らない。

- `cargo fmt --all --check` / `cargo clippy --workspace --all-targets` /
  `cargo test --workspace` の3チェックが通っている
- GUI変更を含むなら手動スモークテストが実施され、DESIGN.md に記録済み
  (`smoke-test-recording` skill 参照)
- コミット前の Codex レビューゲートを通過している(`codex-review-gate` skill 参照)
- 作業ツリーに未コミットの実装差分が残っていない

## 1. バージョン番号を書き換える

**書き換え箇所は4ファイル。** grep で取りこぼしを防ぐこと。

```bash
grep -rn "0\.8\.1" --include="*.toml" --include="*.md" . | grep -v Cargo.lock
```

| ファイル | 箇所 |
|---|---|
| `Cargo.toml` | **2セクション・計4行** — `[workspace.package].version`(6行目付近)と `[workspace.dependencies]` の `mcad-geom` / `mcad-core` / `mcad-io` の version(11〜13行目付近) |
| `README.md` | 5行目付近「現在 **v0.8.1**」 |
| `README.en.md` | 5行目付近「Current version: **v0.8.1**」 |
| `AGENTS.md` | 12行目付近「現在 **v0.8.1**(M8「…」完了)。M9「…」を実装中。」— 完了マイルストーンと進行中マイルストーンも併せて更新する |

各クレートの `Cargo.toml` は `{ workspace = true }` 参照なので**触らない**。

書き換え後に `cargo build` を通し、`Cargo.lock` が更新されることを確認する
(`Cargo.lock` は毎回のリリース差分に含まれる)。

## 2. CHANGELOG.md にエントリを追加する

[Keep a Changelog](https://keepachangelog.com/ja/1.1.0/) 準拠。
`## [Unreleased]` の直下に新しいエントリを積む。

```markdown
## [0.8.1] - 2026-08-12 — v0.8.x 番号外対応

出力(SVG/PDF)のモノクロ化、分割ツールのスナップ対応、ズーム・パンの追加操作手段の3件を実装。
M8完了後の追加改善をまとめてv0.8.1リリース。

### 追加

- (機能ごとに、変更したモジュール・関数・キー割当まで具体的に書く)

### 変更

- (挙動が変わったもの)

### テスト

- 672本 → 709本
```

- 見出しは `## [バージョン] - YYYY-MM-DD — サブタイトル`
- 直後に2〜3行の概要文
- `### 追加` / `### 変更` / `### テスト` の順。該当なしの節は省く
- 箇条書きは**ファイルパス・関数名・キー割当まで書く**のが既存の粒度。
  「〜を追加」だけで終わらせない
- `### テスト` にはテスト本数の増減を書く

## 3. DESIGN.md を更新する

- 該当マイルストーン見出しの「実装未着手」→「実装完了」
- 検収基準の直後に達成記録を追記する:
  `**→ 全項目 v0.8.0 で達成済み(2026-08-11、タスク35a〜44完了)。手動スモークテスト実施済み: …**`
- タスク表の状態を更新する
- 次のマイルストーンの位置づけに影響があれば併せて直す

書式の詳細は `design-record` skill を参照。

## 4. コミットする

**コミットはユーザーの指示を受けてから行う。**

メッセージの文型(既存の履歴に揃える):

```
docs: M8タスク44 ドキュメント整合とv0.8.0リリース
docs: v0.8.1リリース(番号外3件の整理)
```

- 接頭辞は `docs:`(ドキュメントのみの場合)。実装が混ざるなら `chore:`
- 「ドキュメント整合と」+「vX.Y.Zリリース」が基本形
- マイルストーン完了なら「M8タスク44」のように到達点を入れる
- 番号外まとめなら括弧で内容を添える

## 5. タグを付ける

```bash
git tag -a v0.8.1 -m "v0.8.1: <内容の要約>"
```

**注釈付きタグ(`-a`)を使う。** 履歴上は v0.4.0〜v0.7.2 が軽量タグだが、
直近の v0.8.0 / v0.8.1 は注釈付きなので、以後はそちらに揃える。

タグ名は `vX.Y.Z`。マイルストーン完了は `vX.Y.0`、番号外まとめや小修正は
パッチ番号を上げる。

## 6. push する

```bash
git push
git push --tags
```

`origin` は GitHub の public リポジトリ(`Mi-Sakai/mcad`)。
コミットの author はリポジトリローカルに設定済みの noreply アドレスを使う
(設定済みなので通常は意識不要)。

## 補足

- `製図規定.md` は gitignore 対象。リリース差分に現れないのが正常
- 過去のリリースで `資料/` の Codex レビュー記録が同時にコミットされた回がある
  (v0.7.0)。追跡対象なので、未コミットの記録があれば一緒に入れてよい
