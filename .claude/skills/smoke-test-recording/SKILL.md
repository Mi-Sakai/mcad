# 手動スモークテストの依頼・記録手順

このプロジェクト(mcad)は egui によるデスクトップGUIのため、Claude Code
自身がGUIを直接操作して検証することはできない。GUIに関わる変更は必ず
ユーザーによる実機確認(手動スモークテスト)を経て、その結果をDESIGN.md
に記録する運用になっている。fmt/clippy/cargo testなどの自動チェックは
このskillの対象外(通常のビルド確認手順で行う)。

## 手順

1. **検収基準の確認・整備**
   対象タスク/マイルストーンのDESIGN.md該当節に「検収基準」が既にあるか
   確認する。GUI変更を含むなら、必ず「fmt / clippy / workspace test 通過、
   GUI変更は手動スモークテストを記録する」の一文が含まれているか確認し、
   なければ追記する。

2. **チェックリストの作成**
   検収基準を、ユーザーが実機で辿れる具体的な操作手順に分解する。既存の
   記録(例: M7完了時のトリム/延長/フィレット/分割の4ツール検証)に倣い、
   以下の観点を意識する:
   - 操作の開始点(クリック/キー入力)→期待される結果
   - undo 1回での復帰確認
   - エラー・拒否条件(レイヤーロック中、不正な操作など)の確認
   - Esc/ツール切替/ファイル操作などの中断経路での状態不変確認

3. **ユーザーへ依頼**
   作成したチェックリストを提示し、実ウィンドウでの確認をユーザーに依頼
   する。「実機確認をユーザーへ依頼」という既存の言い回しに揃える。

4. **結果の記録**
   ユーザーから確認結果(項目ごとの可否、気づいた問題)を受け取ったら、
   DESIGN.mdの該当「検収基準」節の直後に、既存の記録形式に揃えて追記する:
   `**→ 手動スモークテスト実施済み(YYYY-MM-DD、ユーザー実施): <確認項目を
   列挙>。**` または `**手動スモークテスト(YYYY-MM-DD、ユーザー実施): 問題
   なし。確認項目は...**`
   問題が見つかった場合は、その内容と対応方針も記録する。

5. **コミットメッセージへの反映**
   関連コミットのメッセージに「手動スモークテスト実施済み」を含める
   (既存のコミット履歴の慣習に合わせる)。
