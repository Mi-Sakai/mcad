# mcad — Rust製 2D CAD

Rust + egui で開発する2D CADソフトウェアのMVP実装です。

## ステータス

**v0.3.0（M3「実用化」完了、MVP検収基準を達成）**

- ✅ `mcad-geom`: 幾何プリミティブと計算を実装
- ✅ `mcad-core`: ドキュメントモデルと undo/redo を実装
- ✅ `mcad-app`: ビューポート描画・作図/選択編集ツール・スナップエンジン・レイヤーパネル・ファイル操作を実装
- ✅ `mcad-io`: `.mcad` 保存/読込、DXF入出力を実装（DXF の GUI 結線は M4 予定）

詳細な設計と進行状況は [`DESIGN.md`](./DESIGN.md)、バージョンごとの変更履歴は [`CHANGELOG.md`](./CHANGELOG.md) を参照してください。

## ワークスペース構成

Cargoワークスペースで4つのクレートを管理し、依存方向は一方向のみです。

```
mcad/
├── crates/
│   ├── mcad-geom/  → GUI非依存の幾何プリミティブと計算
│   ├── mcad-core/  → ドキュメントモデル・undo/redo（mcad-geomに依存）
│   ├── mcad-io/    → ファイル保存/読込、DXF変換（mcad-coreに依存）
│   └── mcad-app/   → eguiアプリケーション本体（mcad-ioに依存）
```

| クレート | 役割 |
|---------|------|
| **mcad-geom** | 幾何プリミティブ型（`Point2`, `Vec2`, `LineSeg`, `Circle`, `Arc`, `Polyline`, `Shape`）と計算（最近点、距離、交点）。GUI非依存・純関数のみ |
| **mcad-core** | CADドキュメントモデル（`Document`/`Entity`/`Layer`）とコマンドパターンによる undo/redo |
| **mcad-io** | `.mcad`（JSON形式）の保存/読込と、`dxf`クレート経由のDXF入出力 |
| **mcad-app** | egui による GUI アプリ本体。ツール・ビューポート・スナップエンジン・レイヤーパネル・ファイル操作 |

## 実装済み機能

### 幾何プリミティブ（`mcad-geom`）

- **基本型**: `Point2`（f64）、`Vec2`、`Aabb`
- **プリミティブ**: `LineSeg`、`Circle`、`Arc`（CCW、中心+半径+開始/終了角）、`Polyline`
- **列挙型**: `Shape`（各プリミティブを統一的に扱う）
- **計算関数**:
  - `closest_point(shape, p)` — 最近点（ピック判定・スナップ候補に使用）
  - `distance_to(shape, p)` — 距離（ヒットテスト用）
  - `intersect(a, b)` — 交点計算（線分×線分、線分×円/弧、円×円のすべての組合せに対応）
  - `Aabb` — 軸並行境界ボックス（ビューポートカリング・矩形選択用）
- すべての関数は純関数。プロパティテスト（`proptest`）で検証済み

### ドキュメントモデルと状態管理（`mcad-core`）

- **ID型**: `EntityId`, `LayerId`（`slotmap`キー）
- **型**:
  - `Entity` — エンティティ（幾何 `Shape` + 所属レイヤー + スタイル）
  - `Layer` — レイヤー（名前・色・表示/非表示・ロック状態）
  - `Document` — ドキュメント（エンティティ・レイヤー・カレントレイヤー・履歴を保持）

- **コマンドパターン undo/redo**:
  - すべての状態変更は [`Command`](./crates/mcad-core/src/command.rs) を `Document::apply` に渡すことで実行
  - コマンドは逆操作可能な形で undo/redo スタックへ記録
  - `Document::undo` / `Document::redo` で取り消し・やり直し
  - スナップショット方式より省メモリで、大図面に対応

- **複合コマンド** `Command::Batch`:
  - 複数の変更をツール操作1回の単位でまとめる（例：矩形選択→複数エンティティを一度に移動）
  - サブコマンドをまとめて1つの undo/redo 記録として扱う
  - 原子性を保証：途中でエラーが起きると、それまでの変更をすべて巻き戻す

- **no-op検出**:
  - 空の `Command::Batch` やサブコマンドがすべて意味的 no-op（状態が変わらない）な場合、undo/redo 履歴に記録しない
  - `before == after` の `ModifyEntity` / `SetLayerProps` / `SetCurrentLayer` も同様に履歴を汚さない

- **レイヤーロック機構**:
  - ロック済みレイヤーのエンティティは、追加・変更・削除が拒否される（`CoreError::LayerLocked`）
  - ただし undo/redo はロック判定を迂回し、ロック済みレイヤーに対しても履歴を復帰できる設計

- **ID発行** `NewIds`:
  - `apply()` 後、新規作成されたエンティティ・レイヤーのID一覧を直接受け取れる
  - ツール（選択セット拡張など）の後処理が効率的

### GUI・作図/編集ツール（`mcad-app`）

- **Viewport**: ワールド座標（f64）⇔スクリーン座標（f32）変換。カーソル中心ズーム、パン、ズームに適応するグリッド表示（1/2/5系列）、AABBカリング付きエンティティ描画
- **作図ツール**: Point / Line / Circle / Arc（始点・通過点・終点の3点指定）/ Polyline。未確定の途中経過をプレビュー表示
- **選択・編集ツール**: クリック選択（最近傍）、矩形選択（完全内包判定）、ドラッグ移動、削除。移動/削除は選択全体を `Command::Batch` にまとめ、undo/redo が常に1単位。ロックレイヤーが混在した場合はバッチの原子性により操作全体が失敗する
- **スナップエンジン**: 端点 > 交点 > 中点 > 中心 > グリッド の優先度で候補を1点選択。交点計算はカーソル近傍AABBで事前絞り込み。スナップ先は種別ごとのマーカー（□端点・×交点・△中点・○中心・＋グリッド）で表示

### レイヤーパネル（`mcad-app`）

- **右側パネル**: レイヤー一覧・カレント切替・色変更・表示/ロック切替・追加/削除
- **undo/redo 統合**: すべての変更は `Command` として `Document::apply` へ渡すため、undo/redo の対象になる
- **制約**: デフォルトレイヤー、カレント、非空レイヤーは削除不可（コア側で検証）

### ファイル操作（`mcad-app`）

- **新規/開く/保存/名前を付けて保存**: キーバインド Ctrl+N/O/S/Shift+S に対応
- **ネイティブダイアログ**: rfd クレートで `.mcad` 形式のファイル選択・保存ダイアログを提供
- **未保存確認**: Ctrl+N/Ctrl+O・ウィンドウ閉鎖のいずれも dirty なら egui 内製の非ブロッキングモーダルで確認する（rfd のネイティブ確認ダイアログはメインウィンドウの裏に隠れる/応答なしになる問題があったため不採用。「名前を付けて保存」のファイル選択ダイアログ自体は rfd のまま）
- **ウィンドウタイトル**: ファイル名と dirty 状態（末尾の `*`）を表示
- **dirty 判定の簡略化**: 操作・undo・redo のいずれでも dirty になる方式。保存後に undo で保存時内容へ戻しても未保存扱いになる（M4 で履歴世代ベースへ改善予定）

### `.mcad` 保存/読込（`mcad-io`）

- **ポータブルDTO**: `FileDocument`（レイヤー参照はインデックス方式）へ変換してから JSON 保存
- **往復一致**: import 時は `Document::new()` から `Command` で再構築し、無用な差異を排除
- **バリデーション**: 非有限座標・負半径・空ポリラインを拒否

### DXF 入出力（`mcad-io`）

> **注意**: DXF 入出力は現在 `mcad-io` のライブラリ API（`save_dxf` / `load_dxf`）のみで、GUI からは操作できません。GUI 結線は M4 で対応予定です。

- **対応エンティティ**: LINE / CIRCLE / ARC / LWPOLYLINE / POINT とレイヤー
- **色の近似**: ACI 標準 9 色パレット（1～9）で RGB を最近傍の色へ丸める。パレット外 ACI（10～255）は中間グレー
- **レイヤーロック**: DXF フォーマットが非対応のため、往復ではロック状態が保存されない
- **線幅**: `Style::width` は DXF へ変換されず、往復で既定値（1.0）に戻る
- **未対応エンティティ**: TEXT や DIMENSION など対応外のエンティティは無視し、`ImportSummary` で無視件数を返す
- **堅牢性**: ジオメトリが不正でも DXF ファイル全体の import を失敗させない

## 開発方法

### 起動方法

- `cargo run -p mcad-app`（リリースビルドなら `cargo run --release -p mcad-app`）でアプリを起動する。
- 起動直後はサンプルエンティティ（線分・円・円弧・ポリライン）入りのドキュメントが表示される。動作確認用に意図的に残している挙動で、真に空の文書から始めたい場合は起動直後に `Ctrl+N`（新規ドキュメント）を押す。
- 起動直後の状態は保存済み扱いで、ウィンドウタイトルに未保存マーカー（`*`）は付かない。

### 終了方法

- ウィンドウの閉じるボタン（OSのウィンドウマネージャ）で終了する。アプリ内に終了専用のキーボードショートカットはない。
- 未保存の変更がある状態でウィンドウを閉じようとすると、アプリ内モーダル（見出し「Unsaved changes」、本文「Discard unsaved changes and quit?」）が最前面に表示される。「Discard and quit」を選ぶと変更を破棄して終了し、「Cancel」または背景クリック/Escでは終了をキャンセルしてアプリに戻る。
- 未保存の変更がなければ、確認なしでそのまま終了する。
- Ctrl+N（新規ドキュメント）/Ctrl+O（ファイルを開く）も未保存の変更があれば同様のアプリ内モーダル（本文はそれぞれの操作向けに変わる。「Discard and continue」で実行、「Cancel」/背景クリック/Escで取り消し）で確認する。未保存でなければ確認なしで即座に実行する。

### ビルド・テスト・チェック

```bash
# ワークスペース全体をビルド
cargo build

# mcad-coreの単体テストを実行
cargo test -p mcad-core

# 全ターゲットで lint チェック（警告も厳しく）
cargo clippy --all-targets

# コード整形
cargo fmt
```

### CI

リポジトリには `fmt` / `clippy` / `test` の自動チェックが組み込まれています。

## 設計ドキュメント

プロジェクトの全体設計、技術選定の根拠、タスク分割は [`DESIGN.md`](./DESIGN.md) を参照してください。

主な設計判断：

- **f64 ワールド座標**: CAD の座標精度が重要。f32 は大きな図面で誤差が蓄積。描画時のみ f32 へ変換
- **コマンドパターン undo**: スナップショット方式より省メモリで、大図面でも成立
- **geom を GUI 非依存に分離**: 幾何計算をテスト可能に。将来の拘束ソルバー追加も容易
- **空間インデックス MVP では省略**: 数千エンティティまでは全走査 + AABB カリングで対応
