#### 確定済みの設計方針(2026-08-18 ユーザー承認)

1. **汎用テーブルが土台、部品表は特化版**: `TableGeom`(anchor: ワールド左下、列幅・行高さ・
   文字高さ: 紙 mm、cells: 行×列の文字列)+ `EntityGeom::Table` バリアント。部品表は規定様式の
   列構成プリセット+表題欄直上への配置ヘルパー+行を上方向へ積む配置規則として実装する。
2. **自動集計(エンティティ集計→行生成)は M10 では実装しない — 決定のみ行う**。mcad には
   「1部品」を数える単位(ブロック・グループ・照合番号=風船)が存在せず、風船は引出線前提
   (G3 依存)のため。M10 は手動記入+様式プリセットに留め、「集計単位は風船(G3 後)または
   ブロック概念の導入後に確定して自動集計を再訪する」と記す(M9 設計判断8「決定のみ行い実装は
   G3 へ」と同じ流儀)。ブロック・グループ自体は 2026-08-22 に7章「将来の検討項目:
   グループ化・ブロック化」としてロードマップへ取り込んだ — 同項の段階2(ブロック)が本方針の
   再訪の前提工事の一方となる(もう一方は G3 の風船)。
3. **表は回転非対応**(angle フィールド自体を持たない)。組版・pick・DXF 分解が大幅に単純化する。
   translated / mirrored は anchor のみ変換(Text の MIRRTEXT=0 相当と同じ考え方で内容は
   鏡像化しない)。
4. **セル寸法は紙 mm、core の aabb は 1:1 解釈**(`TextGeom.height` と同じ契約。尺度反映 AABB は
   app 層の責務 — `text_world_aabb` の流儀)。
5. **`.mcad` v6**: Table を1回のバージョン上げにまとめる。v5 DTO は凍結する。
6. **DXF は非対称往復(best-effort)**: export は罫線→LINE・セル→TEXT へ分解、import は
   ACAD_TABLE 系をスキップ+件数計上(G3 の記号と同じ整理)。
7. 検収基準・残る詳細(表ツールのキー割当・ダイアログ構成・プリセット既定値等)は着手時の
   詳細設計で確定する(M4 までと同じ運用)。検収の柱: 部品表つき A4 図面が画面と SVG/PDF で
   規定様式どおりに出る/尺度 1:2 で紙基準拡縮/v5 以前の読込無損失・v6 往復無損失/3境界での
   不正値拒否/`../tcad` の `cargo test --workspace` 通過/DXF 分解 export を他 CAD で開ける
   (手動確認)。

#### 詳細設計(2026-09-06、采配役、着手時に策定)

方針1〜7 を実装可能な粒度へ落とす。数値のうち「規定確定値」と書いたものはタスク55 の承認で
差し替える(それまでは暫定値)。

1. **`TableGeom`(core、`entity_geom.rs`)**:
   `anchor: Point2`(ワールド、表の**左下**)/ `col_widths_mm: Vec<f64>` / `row_heights_mm: Vec<f64>` /
   `text_height_mm: f64` / `cells: Vec<String>`(行優先、**行 0 = 最上段**。表題欄テンプレートの
   `rows` と同じ向き)。`validate`: 行数・列数 ≥ 1、全寸法が有限かつ正、`cells.len() ==
   rows × cols`、`text_height_mm` が最小行高さ未満(文字が行からはみ出さない)、セル文字列は
   `TextGeom` と同じ制約(制御文字禁止。空文字列は**許可** — 空欄が普通にある)。
   `aabb` = `anchor` 〜 `anchor + (Σ幅, Σ高さ)` の 1:1 解釈(方針4)。`translated` / `mirrored` /
   `rotated` は `anchor` のみ変換(方針3。`rotated` も anchor だけ回し表は回さない — Text の
   `MIRRTEXT=0` 相当の割り切りを回転にも適用。回転させたい需要は non-goal)。
   罫線の太さ・セル内パディング・文字の寄せは**保存しない**(app 層の定数: 外枠 0.5mm・内部
   区切り 0.13mm〔当初 0.25 と誤記、実定数に合わせて訂正〕は `frame.rs` の `FRAME_BORDER_WIDTH_MM` / `FRAME_DIVIDER_WIDTH_MM` を再利用、
   パディングは `CELL_TEXT_PAD_MM`、文字は左寄せ・垂直中央の近似 — 表題欄と同じ見え方に揃える。
   右寄せ・中央寄せは non-goal)。
2. **アンカーが左下である帰結**: 行の追加・削除で表は**上方向へ伸縮**し、左下は動かない。これは
   部品表(表題欄直上に置き、行を上へ積む)にはそのまま合致し、汎用表でも「配置した点が動かない」
   という単純な規則になる。汎用表で「下へ伸ばしたい」需要は、移動(`M`)で対応する(non-goal)。
3. **v6(タスク57)**: `FileDocument` に `EntityGeom::Table` を通す(既存の `EntityGeom` serde に
   乗る)+ `DimStyle.arrow_kind`(タスク63 の前提)。v5 DTO 凍結、v1〜v5 は既定値補完。
   読込時の不正値(1 の validate 違反)は拒否。
4. **展開(タスク58、app `table.rs` 新設)**: 純関数 `expand_table(table, k) -> TableExpansion
   { segments: Vec<(seg, width_mm)>, texts: Vec<TextGeom> }`。罫線は紙 mm で組んで `k` 倍
   (`text_world_aabb` と同じ「anchor 基準で k 倍」)、セル文字は `TextGeom { anchor: セル左下 +
   pad, height: text_height_mm(紙 mm 契約のまま), angle: 0 }`。画面は `draw_text` と線分描画、
   plot は `push_dim` と同じ経路(線は stroke、文字は既存の文字アウトライン)。pick は
   `table_world_aabb(table, k)` への距離(Text と同じ)。矩形選択の内包判定も同 AABB。
5. **表ツール(タスク59)**: キー **`K`**(未使用: H/J/K/Q/U/V/W から。H はハッチング用に温存)。
   1クリックで `anchor` を置き(スナップ適用)、既定の 3 行 × 3 列(列幅 30mm・行高さ 8mm・
   文字高さ 3.5mm・空セル)を `AddEntity`。行列数の事前入力は設けない(ダイアログで直す方が
   往復が少ない)。レイヤーはカレント(自動割当なし)。
6. **表編集ダイアログ(タスク59)**: 右パネルに「表」セクション(表を**1つだけ**選択中に表示。
   複数選択は対象外)を置き、「表を編集…」でモーダルを開く(表題欄ダイアログ流儀: 作業コピー →
   OK で `ModifyEntity` 1発 = undo 1単位、キャンセルで無変更、不正値は OK を無効化して理由表示)。
   内容: セルのグリッド(`TextEdit` を行×列に並べ、スクロール)、列幅の数値欄(列ごと)、行高さ
   (全行共通の1欄。行ごとの個別値は保持するが UI では共通値のみ)、文字高さ、「行を上に追加」
   「最上段を削除」「列を右に追加」「右端の列を削除」。日本語ラベル(右パネル・ダイアログは
   日本語化済み領域)。
7. **部品表プリセット(タスク60)**: 「表」セクションに「部品表にする」ボタン。押すと列構成を
   規定の部品欄(暫定: 照合番号 15 / 名称 65 / 個数 15 / 材質 35 / 備考 40 = 170mm、様式 B の
   ときは 12 / 45 / 13 / 25 / 25 = 120mm。**規定確定値はタスク55**)に置換し、**最下段**をヘッダ行
   (列名)にする(部品欄はヘッダが表題欄側 = 下にあり、部品行を上へ積む JIS の流儀)。既存セルは
   列数が変わる場合に切り詰め/空欄補完。「表題欄の上に配置」ボタン(枠有効時のみ有効)は
   `anchor` を `paper_to_world((block_left, block_top), k)` へ動かす(`frame_layout` の表題欄
   左上。幅は表題欄と一致するので右端も揃う)。**自動集計は非対応**(方針2)を doc とダイアログの
   説明文に明記。
8. **DXF(タスク61)**: export は展開結果の線分 → LINE、セル文字 → TEXT(既存の Text export と
   同じ経路。非対称往復として AGENTS.md へ記録)。import は `ACAD_TABLE`(dxf 0.6.1 での実際の
   型名は実測)をスキップして件数計上。
9. **tcad**: `EntityGeom` は `#[non_exhaustive]` で tcad 側に網羅 match は無い(2026-09-06 grep 実測
   0 件)。additive のみ。
10. **non-goal(明記)**: 表の回転・セル結合・右寄せ/中央寄せ・行ごとの UI 個別高さ・自動集計・
    ACAD_TABLE の import・複数表の一括編集。

- **実装時追記(2026-09-06、タスク56、implement-opus の判断を采配役が採用)**: (1) 上限を追加 —
  `MAX_TABLE_MM = 10_000`(個々の列幅・行高さ・文字高さと合計の上限。表題欄の
  `MAX_TITLE_BLOCK_MM` と同値・同根拠)、`MAX_TABLE_ROWS = 512` / `MAX_TABLE_COLS = 64`。
  理由: 個々が有限でも合計が inf へあふれ非有限 AABB を返す穴と、毎フレーム展開される表を
  細工した `.mcad` で GUI を止められる穴(M8 表題欄の Codex 指摘と同じ論点)。512 行は
  「部品表は数十〜100 行規模」という見積もりで規定・実測の裏付けは無い。(2) `cell(r, c)` は
  未検証の値に対しても panic せず `None` を返す全域関数(読込直後・編集途中の作業コピーが触る)。
  (3) `text_height_mm >= min(row_heights)` は等号も拒否。(4) セルの制御文字は `char::is_control`
  で拒否(`\n` `\t` も不可)。**依頼時の前提誤り**: `TextGeom::validate` は制御文字を検査して
  いない(空文字列・非正高さ・非有限のみ)。`TextGeom` 側は変更していない — 揃えるかは M11 の
  残債候補として記録。

#### 検収基準(M10完了の定義)

- 規定に部品欄の節(列構成・配置・推奨寸法)がユーザー承認済みで入っている
- `K` で表を置き、ダイアログでセル・列幅・行高さ・文字高さ・行列の増減を編集でき、OK が undo 1単位、
  キャンセルで無変更、不正値(0 以下・非有限・文字高さ ≥ 行高さ)が core・v6 読込・UI の3境界で
  拒否される
- 「部品表にする」で規定様式の列構成とヘッダ行(最下段)になり、「表題欄の上に配置」で表題欄の
  左上に吸着し右端が揃う。行追加で表が上へ伸び左下が動かない
- 部品表つき A4 図面が画面と SVG/PDF で同じに出る(罫線幅・文字位置)。尺度 1:2 で罫線・文字が
  紙基準 mm で拡縮する
- v5 以前の読込が無損失、v6 往復が無損失(表と `arrow_kind`)
- DXF export を他 CAD で開いて罫線と文字が見える(手動確認)、ACAD_TABLE を含む DXF の import で
  スキップ件数がステータスへ出る
- 寸法矢先 7 種(タスク63)が画面と出力で同一、既定の長さ・角度をユーザー確認のうえ確定
- `../tcad` の `cargo test --workspace`、fmt / clippy / test 通過、GUI 変更は手動スモークテスト記録
