### M11: 性能と互換性(v0.11.0)の設計(2026-09-13 詳細設計、実装完了)

7章「随時対応」の「回転寸法と DXF DIMENSION の一括設計」で決めた3段階構成(M11-0 契約固定 →

#### M11-0 の成果: 契約の固定(2026-09-13、采配役)

**(1) DXF 種別ごとの対応表**(`dxf` 0.6.1 の生成コードと `spec/EntitiesSpec.xml` を采配役が実測、
2026-09-13)。クレートが読める DIMENSION は5型で、`DimensionBase`(共通)+ 型ごとの定義点を持つ。

| DXF 種別(`DimensionType`) | クレートの型 | mcad の写像 | 備考 |
|---|---|---|---|
| Aligned = 1 | `RotatedDimension` | `DimLinear`(`direction = Aligned`) | 13/14 = 計測 2 点、10 = 寸法線の位置 |
| RotatedHorizontalOrVertical = 0 | `RotatedDimension` | `DimLinear`(`direction = Rotated(50°)`) | 50 = 寸法線の角度(度)。**Aligned と同じ型**で `dimension_type` が区別する |
| Radius = 4 | `RadialDimension` | `DimRadial` | 10 = 中心、15 = 円周上の点、40 = 引出長 |
| Diameter = 3 | `DiameterDimension` | `DimDiameter` | 15 = 円周上の点、10 = **その反対側の点**(中心ではない)。結果として両端 |
| AngularThreePoint = 5 | `AngularThreePointDimension` | `DimAngular`(新設) | 13/14 = 角の 2 点、15 = 頂点、10 = 弧の位置 |
| Ordinate = 6 | `OrdinateDimension` | `DimOrdinate`(新設) | 13 = 計測点、14 = 引出線端、10 = 原点、`is_ordinate_x_type` が X/Y |
| Angular(2直線) = 2 | **無し** | スキップ | クレートに `AcDb2LineAngularDimension` の読込分岐が無い |
| 弧長(type 8) | **無し** | スキップ | `DimensionType` に値自体が無い |

- **定義点の意味づけは Autodesk DXF Reference(2018 版)で確認済み(2026-09-13、research-scout、
  采配役が結論を採用)**。確定した内容: Aligned/Rotated は 13/14 が補助線の起点(= 計測 2 点)で
  10 が寸法線の位置。Radius は 10 = 中心・15 = 円周点。**Diameter の 10 は中心ではなく「15 の
  反対側の点」**(当初案の「両端」は結果として同じだが表現を訂正)。3点角度は 15 = 頂点・
  13/14 = 補助線の端点・10 = 弧の位置。Ordinate は 13 = 計測点・14 = 引出線端・10 = 作成時 UCS 原点。
  **ただし文献は「どう書かれるべきか」であり、LibreCAD が実際にそう書くかは別問題**なので、
  タスク67 で実ファイルを突き合わせて確認する(食い違えば実ファイル側に合わせる)。
- **実ファイルによる裏付け(2026-09-13、`mcad-drawing/M11-libre.dxf`、LibreCAD = libdxfrw 0.6.3 が出力)**:
  斜めの辺(115, 163.75)–(243.75, 146)に対する**水平方向の寸法** 1 件を解析した結果、
  `13` = (115, 163.75)・`14` = (243.75, 146) で**計測 2 点そのもの**(同じ 2 点を結ぶ `LINE` が
  図面にある)、`10` = (243.75, 163.75) で**寸法線の位置**(y が寸法線の高さ)だった。
  文献の解釈が実物で裏付けられた。あわせて判明した実装上の注意:
  - **`70` の値は `32` だけ**(種別の整数部は 0 = Rotated)。`AcDbAlignedDimension` の後に
    `AcDbRotatedDimension` マーカーが続くことで Rotated と分かる。
  - **`50`(寸法線の角度)は書かれていない**(既定 0 = 水平)。**欠落を 0 として扱う**必要がある。
  - **LibreCAD は寸法の見た目を anonymous block(`*D1`)として書き、その中に `LINE` を入れる。**
    `2` = `*D1` がその参照。mcad の DXF import は BLOCKS セクションを読まないため、
    **現状この DXF を mcad で開くと寸法が完全に消える**(ユーザー実機で確認、同日)。
    これは設計判断2(寸法を分解して export する)の正しさを裏付ける — DIMENSION だけを書いて
    ブロックを書かない出力は、受け取り側によっては何も表示されない。
  - **未入手の実例**: 整列(Aligned)・半径・直径・3点角度・座標寸法。これらはタスク67 で
    文献どおりに実装し、実ファイルが手に入り次第テストの入力へ追加する。
- **group 70 の構造**: 「下位3ビットが種別」ではなく、**0〜6 の整数値に 32 / 64 / 128 のビットが
  加算される**形(32 は R13 以降常時、64 = Ordinate の X 型、128 = 文字位置がユーザー指定)。
  dxf 0.6.1 はこれを `DimensionType` と `is_ordinate_x_type` /
  `is_at_user_defined_location` / `is_block_reference_referenced_by_this_block_only` へ
  分解済みなので、mcad 側でビット演算はしない。**`is_at_user_defined_location` が真の寸法は
  文字位置が明示指定なので `DimAnnotation::text_anchor` へ写す**(タスク67 で扱う)。
- **group 52(`extension_line_angle`)は絶対角ではなく 50 への加算値**(補助線を斜めにする
  オブリーク補正)。mcad には対応する概念が無いので、0 以外なら警告に計上して無視する。
- **group 1(`text`)の扱い**: 空文字列と `<>` は「実測値を描く」、**スペース 1 文字は「文字を
  出さない」**、それ以外はその文字列を描く。`<>` を含む文字列は前後を接頭辞・接尾辞として
  分解する(v7 の `prefix` / `suffix`)。スペース 1 文字は M11 では `value_override = Some(" ")`
  ではなく**警告して無注記にする**(mcad に「文字を出さない寸法」の概念が無いため。タスク70 で確定)。
- 2直線角度・弧長は import でスキップし件数に計上する。**ただし M10 タスク61 で判明したとおり、
  クレートが `EntityType` を持たない型はパーサ側で読み飛ばされ `entities()` に現れないため
  計上できない。** 2直線角度と弧長がこれに該当するので、「読めない種別があった」ことは
  ユーザーへ伝えられない。この制約を README と import summary の doc に明記する。
- 関連付け(DIMASSOC)はクレートの公開フィールドに無いため、**すべて静的寸法として取り込む**
  (M9 設計判断どおり非関連。図形を動かしても寸法値は追従しない)。

**(2) 角度の単位**: DXF の角度フィールド(50 `rotation_angle`、51 `horizontal_direction_angle`、
52 `extension_line_angle`、53 `text_rotation_angle`)は**度**として扱う。**Autodesk の DXF Reference には
単位の明記が無い(2026-09-13 の調査で確認できず)が、実ファイルの垂直寸法が `50` = 90 と
書いていた(同日、`M11-libre.dxf`)ことから度で確定。**
mcad の角度は**すべてラジアン**
(`TextGeom::angle`・`DimDiameter::angle`・`DimRadial::leader_angle` と同じ契約)。変換は
**io 境界の 1 箇所**(`dxf_file.rs` の import/export 関数)に閉じ、`to_radians()` / `to_degrees()` を
使う。角度を持つ寸法すべてについて「mcad → DXF → mcad」の往復で角度が一致することをテストで
固定する(許容 1e-9 rad)。**core・app は度を一切扱わない。**

**(3) `.mcad` v7 のデータモデル**(M11-1 で 1 回のバージョン上げにまとめる。v6 DTO は凍結):

- `DimLinear` へ `direction: DimDirection` を追加(`#[serde(default)]`、既定 `Aligned`)。
  `#[non_exhaustive] enum DimDirection { Aligned, Rotated(f64 /* ラジアン、絶対角 */) }`。
  水平/鉛直は `Rotated(0)` / `Rotated(π/2)` で表し、**専用バリアントは設けない**(データとしては
  同一で、UI のボタンが角度を入れるだけ。バリアントを増やすと「水平と Rotated(0) のどちらで
  保存するか」という無意味な分岐が core・io・app の3層に生じる)。展開は計測 2 点を
  `direction` の方向へ投影して寸法線の端点を決め、補助線は各計測点から寸法線へ下ろす。
  `Aligned` のときの展開は現行と完全に同一(v6 以前の図面の見た目は変わらない)。
- `DimAngular { vertex: Point2, p1: Point2, p2: Point2, arc_radius: f64, annotation }`(新バリアント)。
  `p1`/`p2` は頂点から見た 2 方向を決める点(距離は寸法線の弧の位置に使わず、`arc_radius` が決める)。
  値は 2 方向のなす角(度表示。単位記号 `°` を付ける)。**許容記号は無し**(`DimKind::Angular` の
  `allowed_symbols` は空)。
- `DimOrdinate { origin: Point2, feature: Point2, leader_end: Point2, axis: OrdinateAxis, annotation }`
  (新バリアント)。`#[non_exhaustive] enum OrdinateAxis { X, Y }`。値は `feature − origin` の
  該当成分。
- `DimAnnotation` へ 3 フィールドを追加(いずれも `#[serde(default)]`):
  - `text_rotation: Option<f64>`(ラジアン。`None` = 既定の読み取り方向規則に従う。
    `Some(0.0)` で水平固定。DXF 53 の写像先)
  - `value_style: ValueStyle`(`#[non_exhaustive] enum { Plain, Reference, TheoreticallyExact }`、
    既定 `Plain`)。`Reference` は値を括弧 `(50)`、`TheoreticallyExact` は枠 `[50]` で囲む。
    **`value_override` とは独立**(上書きした値にも括弧・枠は掛かる)。
  - `prefix: Option<String>` / `suffix: Option<String>`(`2×φ10` の `2×`、`4-M6` の `-M6` 等)。
    DXF group 1 の文字テンプレート(`<>` を実測値へ置換)はここへ写す — `<>` の前後を
    prefix/suffix に分解し、`<>` を含まない文字列は `value_override` とする。
- 全フィールドに既定値があり、既定は現行描画と同値。v1〜v6 は既定値補完で無損失。
  検証(`validate`)は M9 と同じ 3 境界(core コマンド・v7 読込・UI 入力)で行う。

#### 実測: 大規模図面の性能(2026-09-13、タスク66。采配役が再実行して再現を確認)

1,000 / 5,000 / 20,000 エンティティ(線 50%・円弧 20%・ポリライン 10%・文字 10%・寸法 10% を
10,000mm 四方へ決定的に散らした図面)での中央値。release ビルド、開発機での実測。
**egui の実描画は headless で測れないため含まない**(描画の前処理 = カリング + AABB 計算と、
`plot_page` を代理指標にしている)。

| 操作 | 1k | 5k | 20k |
|---|---|---|---|
| pick(命中 / 不命中) | 0.07 / 0.07 ms | 0.45 / 0.44 ms | 1.74 / 1.90 ms |
| 矩形選択(全体 / 一部) | 0.06 / 0.06 ms | 0.37 / 0.33 ms | 1.29 / 1.49 ms |
| `document_aabb`(ズームフィット) | 0.05 ms | 0.30 ms | 2.06 ms |
| 描画前処理(カリング + AABB) | 0.12 ms | 0.63 ms | 3.11 ms |
| `plot_page`(SVG/PDF 出力) | 2.24 ms | 12.28 ms | **49.72 ms** |
| `.mcad` 保存 | 2.04 ms | 7.01 ms | **31.58 ms** |
| `.mcad` 読込 | 3.41 ms | 14.84 ms | **62.29 ms** |

**判断: 空間インデックスは導入しない(タスク76 は見送りとして閉じる)。** 根拠:
- 空間インデックスが速くするのは **pick・矩形選択・カリング**だが、20,000 エンティティでも
  いずれも 3ms 台で、60fps の 1 フレーム予算(16ms)に対して十分速い。索引を入れても削れるのは
  最大でその数 ms で、体感は変わらない。一方で core へ索引の保守(追加・削除・undo/redo での
  整合)という恒久的な複雑さを持ち込む。
- 16ms を超えたのは `plot_page`・保存・読込の 3 つだが、**いずれも全エンティティを必ず処理する
  性質の単発操作**(エクスポート・ファイル操作)で、空間インデックスでは速くならない。
  20k で 30〜60ms なら実用上許容できる。
- 残る未検証領域は **egui の実描画コスト**。これは計測に含まれないので、20,000 エンティティの
  図面を書き出す `export_sample_document_for_manual_check`(`perf_tests.rs`)を用意し、実ウィンドウで
  体感を確認する。**重い場合の対策は空間インデックスではなく描画側**(バッチング・LOD)になるため、
  本判断は変わらない。別課題として扱う。
  **→ 実ウィンドウで確認済み(2026-09-13、ユーザー): 20,000 エンティティの図面でパン・ズーム・
  選択の体感は重くない。** 空間インデックスの見送りはこれで確定。

#### タスク67 の実装時追記(2026-09-13、implement-opus の判断を采配役が検算のうえ採用)

M11-0 で先送りした論点を実装時に決めた。一次情報は `crates/mcad-io/src/dxf_file.rs` の
モジュール doc「DIMENSION の import」と各変換関数の doc。

- **回転寸法の受入条件を「角度が 0 か」ではなく「整列寸法と同じ図になるか」に変えた。**
  計測 2 点の向きが group 50 の方向と平行な回転寸法だけを `DimLinear` として取り込み、
  平行でないものは `skipped_entities` へ計上してスキップする。**采配役が当初出した指示
  (角度 0 のものを Aligned として受ける)は誤りだった** — `M11-libre.dxf` の `*D1`
  (斜辺 (115, 163.75)–(243.75, 146) に付けた水平寸法、group 50 は省略 = 0)で破綻する。
  DXF の値は投影長 **128.75** だが `DimLinear` が描くのは実距離 **129.96778** で、
  **1.218mm が無警告で変わる**(采配役が再計算して確認)。新しい条件では `*D1` が落ち、
  代わりに鉛直寸法 `*D3`(group 50 = 90、計測 2 点も鉛直)が無損失で通る。
  タスク68 で `DimDirection` が入れば両方とも本来の向きで取り込める。
  **教訓**: 「角度の値」ではなく「モデルで表現したときに図が変わらないか」で受入を決める。
- **押し出し法線(210/220/230)が (0,0,1) でない寸法は拒否**し `skipped_entities` に計上する
  (許容 1e-9)。定義点が OCS で書かれるため WCS としてそのまま読むと鏡像・回転した位置に
  置かれる。畳む変換は書けるが結果は別物なので、TEXT の位置基準と同じく「表現できないものは
  変形せずスキップして通知する」方針に合わせた。
- **実測値(42)は使わず座標から再計算**する(M6 設計判断2)。ただし 42 は省略されることが多く
  (実測: libdxfrw 0.6.3 は書かない)、クレート既定値 0.0 と省略を区別できないため、
  **`42 <= 0` は「書かれていない」として比較しない**。書かれている場合のみ相対 1e-6 で比較する。
  **食い違えば取り込まず `skipped_entities` へ計上してスキップする**(直径寸法は直径で比較)。
  当初は「取り込んだうえで `dropped_dimension_details` へ計上する」実装だったが、Codex
  adversarial review の high 指摘で改めた: それでは mcad が DXF の値と**違う値を表示**して
  しまい、回転寸法で防いだ「値が黙って変わる」問題と同種になる。典型的な原因は DIMSTYLE の
  測定倍率(DIMLFAC)で、mcad には測定倍率の概念が無く表現できない。このケースは**幾何は
  平行のまま値だけ食い違う**ため、回転寸法の平行判定(上記)では防げず、42 自体の比較が
  別途必要。判定は `actual_measurement_mismatches`(`crates/mcad-io/src/dxf_file.rs`)。
- **DIMSTYLE(3)は名前ごと黙って捨てる**(警告に計上しない)。外部 DXF はほぼ必ず名前付き
  スタイルを参照するため、計上すると全寸法が警告になりノイズにしかならない。色の ACI 近似・
  未知線種の Continuous フォールバックと同じ「確定的に解釈する」扱い。代わりに
  **「他 CAD で見た寸法の見た目とは一致せず、値と定義点だけが保存される」**ことをモジュール
  doc に明記した。
- **anonymous block(2)は無視**。BLOCKS を読まないので DIMENSION を取り込んでも線が二重に
  入らない(fixture の BLOCKS の LINE 11・SOLID 11・MTEXT 6・ARC 1 が丸ごと無視されることを、
  取り込み後のエンティティ数 10 件で固定した)。
- **警告は 3 段階**。(1) 寸法ごと捨てる = `ImportSummary::skipped_entities`(整列と等価でない
  回転寸法・51≠0 の回転寸法・3点角度・座標寸法・法線が +Z でない・退化・**42 の食い違い**)、
  (2) 取り込むが属性を捨てる = **`ImportSummary::dropped_dimension_details`(新設)**
  (文字テンプレート 1 が空でも `<>` でもない・52≠0・53≠0。寸法 1 件につき最大 1)、(3) 黙って捨てる
  (DIMSTYLE・引出線長 40・文字の寄せ 71・行間 41/72・block 名 2・整列寸法の 51)。
  新カウンタの追加は `mcad-app` の `apply_imported_dxf` にも波及した(分解パターン・テストの
  struct literal・ステータス行 1 本)。

- **fixture は合成データ(2026-09-13、ユーザー指示)**: 写像の検証に使ったユーザーの図面は
  リポジトリが公開されているため同梱せず、**構造(group code の並び・subclass marker・
  anonymous block)を LibreCAD 出力から踏襲したまま座標だけを合成値へ差し替えた**
  `crates/mcad-io/tests/fixtures/synthetic_dimensions.dxf` を置く(采配役が、元図面の図形座標が
  残っていないことを突き合わせて確認済み — 共通するのは原点 0 と直角 90 のみ)。
  写像の正しさは実ファイルで検証済みで、fixture の役割は今後の回帰検出。

**手動スモークテスト(2026-09-13、ユーザー実施、タスク67完了時点): 問題なし。** ユーザーが
LibreCAD で描いた図面を
DXF import して確認した項目は、寸法が 4 件(整列・鉛直・半径・直径)描かれること・半径と直径が
円に正しく付いていること・LibreCAD が anonymous block に入れた見た目の線が二重に入らないこと・
ステータスの文言。
- **Codex adversarial review(high 1件、反映)**: 回転寸法の平行判定は幾何しか見ないため、
  実測値(group 42)が食い違う寸法(DIMSTYLE の測定倍率 DIMLFAC 等が原因)は**幾何が平行のまま
  値だけ違う**。当初は警告に計上して取り込んでいたが、これは同じタスクで防いだ「値が黙って
  変わる」問題そのものなので、**食い違う寸法は取り込まずスキップ**へ変更した(`value_override`
  へ入れる案は、mcad のそれが非比例寸法=下線付きの意味を持つため採らない)。
- **ユーザー実機で判明し修正したもの**: スキップ件数が `1 entity(ies) skipped (unsupported type)`
  と出て理由が伝わらなかった(落ちたのは未対応種別ではなく「表現すると値が変わる寸法」)。
  `ImportSummary::skipped_dimensions` を新設して「表現できないため取り込まなかった寸法」を
  分離し、`1 dimension(s) skipped (cannot be represented without changing the measured value
  or position)` と出すようにした。3点角度・座標寸法(タスク69 で対応予定)は従来どおり
  「未対応の種別」として `skipped_entities` に残す。

#### タスク68 の実装時追記(2026-09-20、implement-opus の判断を采配役が検算のうえ採用)

- **`DimDirection` は `entity_geom.rs` に置いた**(`dim.rs` ではない)。`dim.rs` は「紙 mm と意味だけを
  持ち組版・描画は上位」という注記/スタイルの層で、`DimDirection` は寸法線の位置・測定値・当たり
  判定を決める**幾何**だから。`#[non_exhaustive]`(向きの解決が `unit_vector` 1 箇所に閉じるため。
  `DimKind` を閉じた列挙にしているのは `allowed_symbols` の更新漏れ検出という別の理由)。
- **`Aligned` の展開は一般式に統一せず、従来の閉じた式のまま残した。** 一般式
  (`d2 = d1 + dir·((p2−p1)·dir)`)は数学的には同値だが正規化と内積で最終桁が動きうる。SVG
  スナップショットは座標を文字列化して比較するので、1 ulp の差が fixture 差分になる。
  **「fixture 無変更で 29 ケース通過」をビット単位の同一性で保証**するための意図的な分岐。
- **`offset` の意味を一般化**: 「`p1` から寸法線までの、**寸法線方向の法線**に沿った符号付き距離」。
  寸法線は `p1 + dir.perp() * offset` を通る `dir` 方向の直線で、2 端点は計測 2 点をその直線へ
  投影した点。`Aligned` では `dir = (p2−p1)/|p2−p1|` なので M10 までと完全に同じ意味。
- **`rotated` / `mirrored` が `direction` を変換する**(指示に無かったが必要): 回転は
  `Rotated(θ) → Rotated(θ + angle)`(`DimDiameter::angle` と同じ扱い。加算しないと図形だけ回って
  寸法線の向きが取り残される)。鏡映は `Rotated(θ) → Rotated(2α − θ)` + `offset` 符号反転
  (鏡映 M は向きを裏返すので `perp(M(dir)) = −M(perp(dir))`。導出は doc に記載)。
- **`dim_linear_aabb` を書き換えた**(指示に無かったが必要): 回転寸法では寸法線の端点が計測 2 点の
  箱の外へ出るため、AABB を直さないとズームフィットとカリングが寸法線を取りこぼす。
- **v6 凍結 DTO は `direction` を無視せず拒否する**(`DimLinearV6` の `#[serde(deny_unknown_fields)]`。
  **采配役が再判断して採用**)。黙って無視すると「v6 と自称するファイルの回転寸法が整列寸法へ
  すり替わった図面」が無警告で開き、タスク67 で潰した「値が黙って変わる」問題と同型になる。
  タスク57 の「v5 以前に `Table` を混ぜた偽装ファイルを拒否」と同じ思想。mcad が書く v6 ファイルに
  `direction` は入らないので実運用に支障はない(v1〜v6 の fixture は全て通過)。
- **`direction` は整列寸法でも常に書き出す**(`skip_serializing_if` を付けない)。`DimStyle::arrow_kind`
  の先例に揃えた。副作用として `DimLinear` の JSON は v4 と同形でなくなる(`DimRadial` は同形のまま)。
- **補助線は寸法線の法線方向へ引く**(計測線への垂直ではない)。回転寸法の一般的な描き方だが、
  **`製図規定.md` 5-4 2) a) の「寸法補助線は図形の輪郭線に垂直に引く」との関係は未確認**
  (規定の原文にある回転寸法の扱いを、タスク73 の UI 着手時にユーザーへ確認する)。
  **→ 2026-09-21 ユーザー確認: 既定は「寸法線に垂直」のまま。** 輪郭線に合わせる必要があるときは
  タスク78 の補助線の傾き(作図時は上部パネルの角度欄、既存寸法は右パネル)で指定する運用とする。

#### タスク75 の着手時設計(2026-09-22、UX はユーザー選択、細部は采配役)

**UX 確定(2026-09-22 ユーザー選択)**: グリップは**ドラッグ+スナップ**(M9 の文字位置ドラッグと
同じ流儀)。連続入力は**長さ寸法ツールのモード**(上部パネルのコンボ「単発/直列/並列」)。
並列寸法の寸法線位置は**毎回クリック**で決める(間隔の設定項目は作らない)。一括解除の範囲は
**見た目の上書きだけ**。いずれも app 層のみでスキーマは変えない(M11-2 の方針)。

**(1) グリップ編集**

- **表示**: 選択集合に含まれる可視レイヤーの寸法だけに、スクリーン固定サイズの正方形を描く
  (座標寸法の原点マーカーと同じく `world_to_screen` 後に固定 px)。ロック中のレイヤーの寸法にも
  出す(文字位置ドラッグと同じく、確定時の `Err` をステータスバーへ出す)。
- **種別ごとのグリップ**(→ ドラッグで変わるフィールド。他のフィールドは変えない):

  | 種別 | グリップ | 変わるもの |
  |---|---|---|
  | `DimLinear` | 計測点 `p1`・`p2` | その点。**寸法線は旧寸法線の中点 `m` を通るよう `offset` を再計算**(タスク73 の `linear_offset_preserving_midpoint` と同じ考え方。整列寸法では向きも変わる) |
  | `DimLinear` | 寸法線の中点 | `offset` のみ(`linear_offset(direction, p1, p2, cursor)`) |
  | `DimAngular` | 頂点・`p1`・`p2` | その点 |
  | `DimAngular` | 弧の中点 | `arc_radius = \|cursor − vertex\|` |
  | `DimOrdinate` | 計測点・引出線端 | その点(`axis` は作図時の値を保つ。原点は複数の座標寸法で共有するのが普通なのでグリップを出さない) |
  | `DimRadial` / `DimDiameter` | 円周上の点(引出線・寸法線が円と交わる点) | 角度(`leader_angle` / `angle`)のみ。中心・半径は円の事実なので動かさない |

- **掴む優先順**: ドラッグ開始点が グリップ(スクリーン距離で判定)> 選択中寸法の文字ブロック
  (M9)> 矩形選択。グリップどうしが重なれば選択順の先頭・グリップ定義順の先頭。
- **ドラッグ中**: スナップを効かせる(計測点を図形の端点等へ吸着させるのが主目的。全グリップ共通)。
  直交モード(F8)は基準点が定まらないので効かせない。プレビューは文字位置ドラッグと同じく
  一時コピーを描く。`Esc` でドラッグだけを破棄する。
- **確定**: `Command::ModifyEntity` 1 件(undo 1 回)。移動量がピック許容量未満なら何もしない。
  結果が退化する(`validate` が拒否する、または作図ツールが拒否する条件 — 長さ寸法の投影長ゼロ・
  角度寸法の同方向/反平行・引出線長ゼロ等)ときは**確定せずステータスバーへ理由を出す**
  (「UI は core より厳しく拒否してよい」方針、タスク74)。

**(2) 直列寸法・並列寸法(長さ寸法ツールのモード)**

- 上部パネルに向きのコンボとは別の 2 つ目のコンボ「連続: 単発/直列/並列」を出す。`Tab` は
  向きの循環に使用中なので割り当てない。`spawn()` のたびに「単発」へ戻る。
- **1 本目は単発と同じ 3 クリック**。確定時に**解決済みの向き**(ortho 自動判定を含む)を固定し、
  2 本目以降はその角度の `DimDirection::Rotated(θ)` で作る(1 本目が整列でも、2 本目以降は
  寸法線を同一直線上/平行に揃えるため `Rotated` で保存する。右パネルでは「任意角」等と表示される)。
- **直列**: 前の寸法の `p2` が次の `p1`。**1 クリック(次の計測点)で確定**し、寸法線は 1 本目と
  同一直線上(`offset` は 1 本目の寸法線が通る点から求める)。
- **並列**: 1 本目の `p1` を基準に固定。**2 クリック(次の計測点 → 寸法線位置)で確定**。
- 補助線の傾き(上部パネルの角度欄)は 1 本ごとに確定時の入力値を使う。
- 投影長ゼロは確定を拒否して状態を据え置く(単発と同じ)。
- **系列の打ち切り**: 向き・連続モードを変えたら系列を破棄して `p1` 待ちへ戻る。`Esc` は従来どおり
  ツールを抜ける。
- **確定失敗(ロック中のレイヤー等)でも系列を失わない**: `DimLinear` を
  `keeps_state_on_commit_failure` の対象に加え、`on_commit_failed` で失敗したクリックの前進を
  巻き戻す(タスク74 の座標寸法と同じ扱い)。

**(3) 見た目の上書きの一括解除**

- 右パネル「寸法」にボタンを 1 つ置き、選択中の寸法すべてについて `decimals_override`・
  `text_anchor`・`text_rotation`・`value_override` を `None`、`arrow_placement` を `Auto` へ戻す。
  `Command::Batch` 1 件(undo 1 回)。対象が 1 件も上書きを持たなければボタンは出さない。
- 記号・公差・`value_style`・接頭辞/接尾辞は寸法の意味そのものなので残す。向き・補助線の傾き
  (`DimLinear` のフィールドで注記ではない)も対象外。

#### タスク75 の実装時追記(2026-09-22)

着手時設計の (1)(2)(3) をすべて実装した。app 層のみで完結し、`mcad-core`/`mcad-io`/`mcad-geom`
の公開 API・スキーマは変更していない。

- **グリップの識別子・算出は `tool.rs` に集約した**: `DimGripKind`(11 種)と
  `dim_grips(geom: &EntityGeom) -> Vec<(DimGripKind, Point2)>`(純関数)を新設し、
  `SelectTool`・`main.rs` の双方から使う。各点は種別ごとの独自計算をせず、既存の
  pick 用公開関数(`linear_pick_segments`/`radial_pick_segments`/`diameter_pick_segments`)
  またはフィールドから直接求める(展開・pick と同じ骨格を共有し、描画位置とグリップ位置が
  ずれない)。**角度寸法の弧の中点だけは例外**で、核の `angular_frame`(非公開)を複製せず
  `vertex + normalize(u1+u2) * arc_radius`(2 辺の単位方向の和を正規化した二等分方向)という
  公開フィールドだけから求まる同値の式を使った(`DimAngular::directions()` は公開 API)。
- **ドラッグ確定の規則は `apply_dim_grip(geom, kind, world) -> Result<EntityGeom, String>`
  1 箇所に閉じた**(`tool.rs`、`pub(crate)`。`main.rs` のゴースト描画と
  `SelectTool::end_grip_drag` の両方が同じ関数を通るため、プレビューと確定が食い違わない)。
  判定は「作図ツールが同種のクリックで課す UI 側の追加拒否」(長さ寸法の p1≈p2・投影長ゼロ、
  角度寸法の頂点一致・同方向・反平行・半径ゼロ、座標寸法の引出線長ゼロ、半径/直径寸法の
  中心一致)を先にかけ、最後に `EntityGeom::validate()` を通す(タスク74 の「UI は core より
  厳しく拒否してよい」方針)。角度寸法の4条件は `DimAngularTool` と丸ごと同じ式を
  `check_angular_degenerate` へ共有し、複製しなかった。
- **長さ寸法の p1/p2 グリップは、タスク73 の `linear_offset_preserving_midpoint` と同じ
  「旧寸法線の中点を保つ」考え方だが基準点が違う**: 向き変更(p1/p2 不変)は `dim.p1` を
  基準に使えたが、グリップは点そのものが動くため、新しい基準点(移動後の p1/p2)を使う
  別関数 `linear_offset_for_moved_point(old, new_p1, new_p2)` を新設した(同じ関数を
  流用すると基準点がずれて中点を保てない)。
- **グリップのヒット判定はスクリーン座標で行う**: 表示がスクリーン固定 px の正方形
  (`GRIP_SIZE_PX = 8.0`、原点マーカー `ORIGIN_MARKER_PX = 6.0` と同系統の値だが、
  グリップは指でも掴みやすいよう気持ち大きめにした)なので、ワールド座標の `label_box`
  (M9 の文字ブロック)とは異なりヒット許容量もスクリーン px(`GRIP_HIT_PX = GRIP_SIZE_PX`)

  `handle_select_input` の `drag_started_by` 分岐で「グリップ命中→文字ブロック命中→矩形選択」の
  順に試す形で実装し、グリップどうしが重なる場合のタイブレークは選択順→`dim_grips` の
  返す順(`DimGripKind` の列挙順)で最初に当たったものを返す。

  当たり判定、文字ドラッグの掴んだ点、矩形選択の始点を揃えて押下点で決める(M9 の文字ドラッグと

  しまう。`drag_stopped_by` 分岐でも解放位置へスナップを掛けて `on_grip_drag` してから

- **グリップドラッグはスナップを効かせるが、直交モード(F8)は効かせない**: `SelectTool` に

  従来どおりスナップなし。

  (`None`/`Commit(Command)`/`Rejected(String)`。`PlacementOutcome`/`OffsetOutcome` と同じ設計)。

#### タスク80 の着手時設計(2026-09-22、UX はユーザー選択、細部は采配役)

平行でない 2 本の直線オブジェクトを選び、その交点(延長上でもよい)を頂点とする `DimAngular` を作る。
app 層のみで、保存形(頂点・p1・p2・弧半径)と `mcad-core`/`mcad-io` の公開 API は変えない。
寸法は非関連(M6 設計判断2)で、拾った直線は作成時の値を写し取るだけ。

- **入り口は既存の角度寸法ツール(`Shift+G`、`DimAngularTool`)のモード切替**(ユーザー選択):
  `variant_options`/`set_variant` で上部パネルに「3 points / 2 lines」のコンボを出し、`Tab`
  (`InputEvent::Cycle`)でも循環させる(座標寸法の `OrdAxisMode` と同じ作り。上部パネルは英語の
  領域なのでラベルも英語)。モードを切り替えたら進行中の入力は捨てて各モードの最初の状態へ戻す。
  `spawn()` の既定は 3 points(タスク74 の既存挙動を変えない)。
- **2 lines の操作は 線1 → 線2 → 弧の位置 の 3 クリック**。線のクリックは `wants_shape_pick`/
  `on_shape_pick`(フィレットと同じ経路、スナップなし)で当て、弧の位置は通常の `Click`
  (スナップあり)で受ける。
  - 拾える対象は線分(`Shape::Line`)とポリラインの辺(クリック点に最も近い辺。閉じたポリラインは
    閉じ辺を含む)。円・円弧・その他は理由付きで拒否し、状態は据え置く。
  - 同じ線分を 2 回拾うのは平行として拒否される。同じポリラインの別の辺は許す。
  - 2 本の無限直線が平行・反平行(方向のなす角が 0 または π から `DIM_ANGULAR_ANTIPARALLEL_EPS`
    以内)なら 2 本目のクリック時点で拒否し、1 本目は保持する(フィレットと同じ「2 本目だけ選び
    直せる」)。
- **測る角は弧の位置クリックで決める**(ユーザー選択。AutoCAD と同じ): 2 直線が作る 4 つの角の
  うち、頂点から見てクリック点を含む角を測る。2 直線の単位方向 d1・d2 を基底として
  `c − vertex = α·d1 + β·d2` と分解し(`α = (c−vertex)×d2 / (d1×d2)`、`β = d1×(c−vertex) / (d1×d2)`)、
  `u1 = sign(α)·d1`・`u2 = sign(β)·d2` を 2 辺の向きとする。半径は `|c − vertex|`。
  クリック点がどちらかの直線上(`c − vertex` の単位ベクトルと d1 または d2 の外積の絶対値が
  `DIM_ANGULAR_ANTIPARALLEL_EPS` 以下で符号が定まらない)なら、既存の拒否と同じ流儀で
  拒否する。弧位置待ちの間はカーソル位置で同じ計算をしてプレビューを描く(角の切り替わりが
  見えるように)。
- **p1/p2 の置き場所**: 保存形の p1/p2 は向きだけを決める(`expand_angular` の doc)が、グリップ
  (タスク75)の位置になるので実形状の上に置く。各辺について、拾った線分の端点のうち u 方向
  (`(端点 − vertex)·u > DIM_DEGENERATE_EPSILON`)にあって頂点から最も遠いものを採る。該当する
  端点が無い(補角側を測るなど、実線が無い向き)なら `vertex + u * arc_radius`。
- **確定前の検証は既存の `check_angular_degenerate` と `EntityGeom::validate()` を通す**
  (3 points と拒否の基準を共有する。タスク75 の方針)。
- **確定後は 1 本目待ちへ戻る単発**(3 points と同じ)。確定失敗時の扱いも 3 points の既存挙動に
  合わせ、`keeps_state_on_commit_failure` には加えない。
- **拾った直線は形状のスナップショットなので、undo/redo・ファイル操作の後は捨てる**:
  `ToolKind::DimAngular` を `caches_picked_shapes` の対象に加える。ただし作り直しでモードが
  3 points へ戻らないよう、`reset_picked_shape_tool` で作り直す前のモードを引き継ぐ
  (2 lines のまま 1 本目待ちへ戻る)。
- **プレビュー**: 1 本目を拾ったらその線分(ポリラインなら拾った辺)をハイライト、2 本目の後は
  弧位置待ちのプレビューに加えて、頂点が線分の外(延長上)にあるときは線分から頂点までの延長を
  細線で示す。
- **スコープ外**: 円弧・円の接線を辺とする角度、優角(180° 超)、仮想交点スナップ(M12 で扱う。
  交点計算を共有できるならそのとき寄せる)。
- **検収基準**: (i) 角度寸法ツールで「2 lines」を選び(コンボ・Tab の両方)、交わる 2 線分・
  フィレットで角が欠けた 2 線分・ポリラインの 2 辺のそれぞれで、交点(延長上を含む)を頂点と
  する角度寸法が作れる。(ii) 弧の位置を 4 つの角へ動かすとプレビューがその角に切り替わり、
  確定した値が一致する(鋭角と補角の和が 180°)。(iii) 平行な 2 線・円弧・同じ線分は拒否され
  ステータスに理由が出て、平行のときは 1 本目が残る。(iv) 確定後の寸法のグリップ(p1/p2)が
  実線の上に出て、undo 1 回で消える。(v) 2 lines で 1 本目を拾った後に undo すると 1 本目待ちへ
  戻り、モードは 2 lines のまま。(vi) 3 points の操作は従来どおり。(vii) fmt / clippy / workspace
  test 通過、手動スモークテストを記録する。

#### 設計判断

1. **展開の純関数を `mcad-core` へ移す**(タスク71)。現状 `crates/mcad-app/src/dimension.rs` と
   `table.rs` にある展開(罫線・文字・矢先の座標を組む純関数)は app 層にあり、`mcad-io` から
   使えない。そのため M10 タスク61 の DXF 表 export は**組版を io 側へ再実装しており、値が
   乖離しても検出できない残債**になっている(M10 詳細設計の実装時追記)。寸法の分解 export
   (下記2)で同じ二重化を繰り返さないよう、**展開を core へ移してから export を書く**。
   移設後は app(画面)・io(DXF)・plot(SVG/PDF)が同じ実装を共有する。
   - 移せる根拠: 展開は `TextGeom`(core)・`Shape` / `arrow_glyph`(geom)しか使わず、egui にも
     `Document` にも依存しない。表示モード(F9)による寸法の大きさ解決は `DimRender` の
     引数(ワールド長)として呼び出し側に残るので、core は表示状態を知らないまま保てる。
2. **寸法・表は「分解して export」する**(2026-09-13 ユーザー選択、タスク72)。寸法線・補助線・
   矢先・文字を `LINE` / 塗り(`SOLID` またはポリライン)/ `TEXT` へ分解して書く。理由:
   (a) DXF の `DIMENSION` は見た目を構成する anonymous block への参照を持ち、それを書かないと
   ビューアによっては何も表示されない。(b) 分解なら LibreCAD を含むどのビューアでも確実に
   見える。(c) 表(M10)と同じ流儀で一貫する。**非対称往復**(読み戻しても寸法エンティティには
   戻らない)であることを README・AGENTS.md・import summary の doc に明記する。
   `.mcad` が正本であるという既存の位置づけ(DXF は交換用)は変えない。
   - **実装時の設計方針追記(2026-09-21、采配役判断、タスク72)**: 分解先のうち**矢先の
     塗りは DXF `SOLID`** とする(`dxf` 0.6.1 に `HATCH` に相当する型が無いため実測で確認)。
     `fill_polygon_to_dxf_solids` が凸多角形を頂点 v0 を要とする三角形扇へ分割し、
     `third_corner == fourth_corner` の三角形 `SOLID` 1 枚ずつへ写す(`ArrowKind::ClosedFilled`
     は矢1個につき1枚、`Dot`(16角形近似)は14枚)。輪郭ポリラインにしないのは、塗りが無いと
     ビューアによっては黒塗り矢先が中抜きに見えるため。**代償として非対称の度合いが表より
     強い**: `SOLID` は `dxf_entity_to_geom` が対応しないため、re-import で
     `ImportSummary::skipped_entities` へ計上される(`LINE` / `ARC` / `TEXT` は通常どおり
     Shape / Text として取り込まれる)。回帰テストは
     `reimporting_exported_dimension_skips_only_the_solid_arrow_fills`。
   - **実装時の設計方針追記(2026-09-21、采配役判断、タスク72)**: 寸法由来のエンティティは
     **常に `CONTINUOUS`**(画面・SVG/PDF と同じく、寸法は製図慣行として常に実線で描く)。
     `Style::linetype` による線種上書きは適用せず、色・線幅は他のエンティティと同じ経路で
     適用する(`export_dxf` の `force_continuous`)。また `DimExpansion::texts` の `height` は
     **既にワールド長**(`TextGeom` 本来の紙 mm 契約とは逆)なので、`text_to_dxf_entity` の
     `height * k` を通さず共通ヘルパー `text_geom_to_dxf_text` へワールド長のまま渡す
     (二重換算の防止)。`DimRender` の組み方は SVG/PDF 出力(`plot::plot_page`)と同一。
3. **空間インデックスは計測してから決める**(タスク66 → 76)。現状の実測が無いまま導入すると、
   効果の無い複雑さを core へ持ち込む。数千エンティティの図面で描画・pick・矩形選択・
   ズームフィットの時間を測り、**閾値(例: 1 フレーム 16ms を超える規模)が実在することを
   確認してから**導入する。不要と判明したら「計測結果と見送りの判断」を記録して閉じる。
4. **品質項目を先に置く**(タスク64・65)。M11-1 は寸法モデルを広げるため、既存の寸法描画が
   変わっていないことを機械的に保証する土台(SVG スナップショット)と、v1〜v6 の実ファイルを
   読める保証(fixture)が先に要る。
5. **non-goal(明記)**: 2直線角度寸法・弧長寸法(クレートが読めない)/ 関連付き寸法の追従
   (非関連のまま)/ DIMSTYLE の完全な写像(単一 `DimStyle` へ丸め、落ちる情報は警告)/
   ACAD_TABLE の import / 引出線・幾何公差・表面性状(G3)/ 図面枠の DXF 出力(v1.0.0 後の課題)/
   部品表の自動集計(M10 設計方針2)。
6. **寸法補助線の傾きを `DimLinear` が持つ**(2026-09-21 ユーザー選択、タスク78)。
   `ext_angle: Option<f64>`(絶対角・ラジアン・CCW、`None` = 寸法線に垂直)を足す。
   理由: (a) 製図規定 5-4 2) a)「寸法補助線は図形の輪郭線に垂直に引く」を回転寸法でも
   満たせるようにする — mcad の寸法は非関連で図形への参照を持たないため、輪郭線の向きは
   **ユーザーが指定する**しかない。(b) DXF の `RotatedDimension::extension_line_angle`
   (group 52)に対応する概念で、現在は「mcad に概念が無い」として
   `ImportSummary::dropped_dimension_details` へ捨てている情報が往復できるようになる。
   - **既定(`None`)は現行の描画をビット単位で保つ**: `linear_frame` は `None` のとき
     現行のコードパス(`d1 = p1 + dir.perp() * offset`)をそのまま通す。タスク64 の
     スナップショット36ケースが回帰網。
   - **`Some(θ)` のとき寸法線の端点 `d1`/`d2` は交点で決まる**: 「計測点を通り角度 θ の
     直線」と「寸法線の直線」の交点。寸法線の直線そのもの(`offset` の意味)は変えない。
   - **表示値(`measured_value`)は変えない**。寸法線方向への投影長のままで、
     補助線の傾きでは動かない(AutoCAD の oblique dimension と同じ)。
   - **補助線が寸法線と平行(交点が出ない)なら補助線を描かない**。寸法線と値は描く。
     退化を黙って別物へ倒さない既存流儀(`linear_frame` が `None` を返す経路、
     表の「空セルは出さない」)に合わせる。`validate` は非有限の θ だけを 3 境界で拒否する。
   - **`.mcad` は v7 へ相乗りする**(v7 は未リリースのため。タスク69・70 と同じ扱い)。
   - **実装時の設計方針追記(2026-09-21、采配役判断、タスク78)**: 設計判断6 が触れて
     いなかった 3 点を、実装で次のとおり決めた。
     - **矢の内外判定は「寸法線の実長」(`|d2 − d1|`)で行う**(表示値ではない)。判定は
       「矢とラベルが実際に引かれる線に収まるか」の判断なので、投影長ではなく実長が
       正しい。傾けた回転寸法では両者が食い違うため、矢が外向きに倒れることがある。
     - **補助線が寸法線と平行なときは、端点を垂線の足へ倒したうえで補助線だけ描かない**
       (`LinearFrame::draw_ext_lines`)。θ は 2 本の補助線で共有されるので平行判定は
       両方同時に決まり、端点ごとの真偽値は嘘の一般性になる。判定は
       `|sin(θ − φ)| <= mcad_geom::EPS`。
     - **ほぼ平行(EPS をわずかに超える角度)では交点が遠方へ飛ぶ**。当初はこれを
       「数学的には正しい挙動」としてタスク73 の UI 側の案内・制限に委ねる方針にしたが、
       **Codex adversarial review [medium] 指摘を受けて core 側でガードする方針へ改めた
       (2026-09-21)**。`validate` を通った有限値(例: 閾値直上の `sin = 1e-9` と
       `offset = 1e10`)でも座標が 1e19 へ飛び、`offset` がさらに大きければ Infinity に
       なるため、UI の案内では塞げない。`oblique_foot` が (a) 分母が `EPS` 以下、
       (b) 結果が非有限、(c) 補助線長が `max(|offset|, |p2 − p1|) * MAX_EXT_LINE_SPAN_RATIO`
       (= 1000 倍。補助線と寸法線のなす角がおよそ 0.057° 未満に相当)を超える、の
       いずれかで交点を却下し、**平行時と同じ退化経路**(端点は垂線の足、補助線は描かない)
       へ落とす。判断は `linear_frame` の 1 箇所に閉じ、展開・pick・AABB が同じ結果を見る。
       **UI 側(タスク73)の役割は入力時の案内に限る**。
   - **(b) の撤回: DXF group 52 は取り込まない(2026-09-21、Codex adversarial review
     [high] 指摘 → 采配役が一次資料で裏取りして判断)**。上記(b)は「group 52 が往復
     できるようになる」としていたが、**基準角が確定できない**ため取り込まず、従来どおり
     `ImportSummary::dropped_dimension_details` へ計上する。
     - Autodesk DXF Reference(Linear and Rotated Dimension Group Codes)の原文は
       "When added to the rotation angle of the linear dimension (group code 50), it gives
       the angle of the extension lines" で、**52 は絶対角ではなく group 50 への加算**と読める。
     - ところがこの式をそのまま読むと **52 = 0 で補助線角度 = 50 = 寸法線と平行**になり、
       実際の「52 = 0 は寸法線に垂直」(ezdxf のサンプル `0 = orthogonal to dimension line`、
       AutoCAD ユーザーガイド "Extension lines are created perpendicular to the dimension
       line")と**矛盾する**。整列寸法での基準は、group 50・52 が `AcDbAlignedDimension` の
       group code 表に**存在しない**ため確定できない。実ファイルでの検証もできていない。
     - **group 53(寸法文字の回転)とまったく同じ構造**(基準が復元できないため一度実装した
       変換を撤回して計上へ戻した、タスク70)であり、M11 の判断基準「値や位置が変わる
       取り込みはしない」に従う。
     - **mcad 側の `ext_angle` 機能は残る**(作図・`.mcad` v7・DXF への分解 export は動く)。
       影響を受けるのは DXF **import** だけ。実ファイルで基準を確定できたら
       `θ_ext = 50 + 52` で取り込む形へ移行できる。

#### 検収基準(M11完了の定義)

- 他 CAD が書いた DXF の Aligned / Rotated / Radius / Diameter / 3点角度 / Ordinate の寸法が
  読め、定義点の意味が実ファイルで検証済み(推測のまま実装していない)。2直線角度・弧長は
  読み飛ばされること(および件数に計上できないこと)が doc に明記されている
- DXF の角度が度で、mcad がラジアンであることが io 境界の 1 箇所に閉じており、角度を持つ
  寸法すべてで往復一致がテストで固定されている
- 回転寸法(水平/鉛直/任意角)・角度寸法・座標寸法が作図でき、画面と SVG/PDF で同一に描かれる。
  `Aligned` の描画は v0.10.0 と一致する(スナップショットで確認)
- 注記の拡張(文字回転・参考/理論寸法・接頭辞/接尾辞)が記入でき、3境界で不正値を拒否する
- 寸法補助線の傾き(設計判断6)を作図時・右パネルの双方から指定でき、SVG/PDF・DXF の
  分解 export にも同じ向きで出る。**DXF import は基準角が確定できないため取り込まず
  計上する**(設計判断6 の「(b) の撤回」)。傾き未指定の描画は v0.10.0 と一致する
  (スナップショットで確認)
- 寸法・表が DXF へ分解 export され、LibreCAD で罫線・文字・矢先が見える(手動確認)。
  非対称往復であることが README・AGENTS.md に明記されている
- `.mcad` v6 以前の読込が無損失(v1〜v6 の fixture で固定)、v7 往復が無損失
- 大規模図面の実測値が記録され、空間インデックスの要否がその数値で判断されている
  (導入したなら実測で改善が確認でき、見送ったなら根拠が記録されている)
- 展開の純関数が core にあり、app・plot・io が同じ実装を使っている(M10 の組版二重化が解消)
