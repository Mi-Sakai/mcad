#### 着手前に確認した事実(2026-09-23、采配役がコードで確認)

- `mcad_geom::Shape` は `#[non_exhaustive]` **ではなく**、tcad が網羅 match している
  (`tcad-kit/src/selector.rs`)。**構築線を `Shape` に足すと tcad が壊れる** → `EntityGeom`
  (`#[non_exhaustive]`)へ足す(M12 行の方針どおり)。
- `TableGeom`・`mcad_core::SheetMeta` は tcad から参照されていない(tcad は自前の `SheetMeta` を持つ)。
  フィールドの追加は tcad に影響しない。
- `Polyline` は直線の辺だけを持つ(バルジ無し)。**円弧はポリラインへ結合できない**。
  フィレット(`fillet_lines`)も線分どうしのみ。
- `dxf` 0.6.1 は spec に `XLine`(10 = 基点、11 = 単位方向ベクトル)と `Ray` を持ち、生成コードに
  `XLine` がある(`target/debug/build/dxf-*/out/generated/entities.rs`)。**import/export の実際の
  挙動はタスク91 で確認する**(確認できず — 生成されていることのみ確認)。
- 作図ツールは基点を `Tool::ortho_origin()` で公開しており、スナップが当たった点には直交モードを
  掛けない(`resolve_click_point`、main.rs)。M12 の相対入力・極トラッキング・垂線/接線スナップは
  この基点を共有する。
- 使用中のキー(ツール切替): `D`/`Shift+D`・`S`・`1`・`L`・`C`・`A`・`I`・`P`・`T`・`K`・
  `G`/`Shift+G`・`Shift+V`・`X`・`E`・`F`・`B`。選択モード: `M`/`Shift+M`・`R`(Shift 不問)・`O`。
  `L`/`C`/`P`/`F` は現状 Shift の有無を見ていない(Shift 併用も同じツールになる)。

#### 設計判断

1. **表の種類は `TableGeom` のフィールドで持つ**(タスク81)。`kind: TableKind`
   (`#[non_exhaustive] enum TableKind { Table, Bom }`、既定 `Table`)。別バリアント
   (`EntityGeom::Bom`)にしないのは、描画・編集・DXF 分解 export が表と完全に同じで、種類の
   違いは「部品表の操作を許すか」と「1 図面 1 つ」だけだから。
   - **部品表は 1 図面に 1 つ**を core の不変条件にする: `Document::apply` は部品表を 2 つにする
     `AddEntity` / `ModifyEntity` を `Err` で拒否する(`Batch` なら全体をロールバック)。
     手編集で部品表を 2 つ持つ `.mcad` は読込が失敗する(不正な表と同じ扱い)。
   - **図面ごとの「部品表を使う」**(2026-09-23 ユーザー要望・確定): 計画図・見積図など部品表の
     要らない図面のため、`SheetMeta` に既定 ON の真偽値を足す(`.mcad` に保存。`Default` derive との
     整合から否定形のフィールド名にするかは実装時に決める)。**OFF は「`K` で部品表を自動で
     作らない」だけの意味**で、既存の部品表は消さず、表示・出力も変えない(ユーザー確定)。
     新規図面の既定は ON。
   - **`.mcad` v8 はタスク81 で上げ、構築線(タスク91)が相乗りする**(v8 は M12 の間は未リリース。
     M11 の v7 と同じ運用で、リリース単位の版上げは 1 回)。v7 の DTO は凍結し、v7 以前の表は
     すべて `Table`、「部品表を使う」は ON として読む。**v7 以前の旧部品表は自動で部品表にしない**
     (中身から推測しない。7章「部品欄の列構成の見直し」最終形の教訓)。
2. **`K` の振る舞い**(2026-09-23 ユーザー確定): 「部品表を使う」が ON で図面に部品表が無ければ
   **部品表を置く**。見出し行 + 空の部品行 3 行、列構成と列幅は表題欄の様式から
   (`bom_preset_columns`)。図面枠が有効なら **`K` を押した瞬間に**表題欄の直上へ置き
   (クリックを待たない)、選択モードへ戻って部品表を選択状態にする。undo 1 回で消える。
   図面枠が無効なら従来どおりクリック位置へ置き、列幅は様式A/C。それ以外(OFF、または部品表が
   既にある)は従来どおり汎用表を置く。
   - 右パネル「表」: 「部品表にする」は**選んだ表を部品表に指定する操作**として残す(旧部品表の
     移行経路。列の移し方は v0.11.1 のまま)。図面に別の部品表があれば拒否してステータスバーへ
     出す。部品表を選んでいるときは同じボタンで様式への再適用(現行どおり)。**「表に戻す」**を
     足す(部品表 → 表。中身は変えない)。
   - **部品表を含む複製(`Ctrl+D`)は拒否する**(ステータスバーへ出す)。複製した側を黙って表へ
     変える案は採らない(値や種類を黙って変えない流儀)。部品表を元に表を作りたいときは、複製前に
     「表に戻す」。
3. **数値入力はカーソル横の入力欄**(2026-09-23 ユーザー選択。AutoCAD の動的入力に相当)。
   - 点を受け付ける作図ツールの使用中に `0`〜`9`・`.`・`-`・`@` を打つと、カーソル横に入力欄が
     開く。書式は `x,y`(絶対)・`@dx,dy`(基点からの相対)・`L<A`(基点から長さ L・角度 A 度、
     +X から CCW)・`L`(基点からカーソル方向・極トラッキング中は追跡方向へ長さ L)。
     基点は `Tool::ortho_origin()`。基点が無い段階で相対系の書式を打つと拒否してステータスへ出す。
   - `Enter` で確定し、ツールへは通常のクリック(`InputEvent::Click`)として渡す。入力欄が空の
     `Enter` は従来どおり `Confirm`。`Esc` は 1 回目で入力欄を閉じ、2 回目で従来のキャンセル。
     入力値にはスナップ・直交・極トラッキングを掛けない(明示値が優先)。
   - 解釈は app 層の純関数(`&str` → 点、基点・カーソル方向を引数)で持ち、headless テストで固定する。
     度 → ラジアンは UI 境界に閉じる(M11 タスク73 と同じ)。
   - **代償(ユーザー了承済み)**: 作図ツールの使用中は数字キーが入力欄へ行くので、`1`(点ツール)の
     切替は選択モードからしか効かなくなる。
   - 対象: 点・線分・円・円弧・ポリライン・アイソメ円・矩形・正多角形・構築線、選択モードの
     移動・複製の配置(基点 → 目的点)。図形を当てるツール(トリム・延長・フィレット・面取り・分割)と
     寸法ツールは対象外(寸法は既存図形の点を拾う操作なので、要望が出てから)。
4. **極トラッキング**(タスク84): `F10` で切替、刻み角は 15°/30°/45°/90° から選び `config.json` に
   保存する(既定 15°)。基点があるとき、カーソル方向が刻み角の倍数から一定の画面角度以内なら
   その方向へ吸着し、点線と角度を表示する。**直交モード(F8)とは排他**(片方を入れると他方が切れる。
   AutoCAD と同じ)。スナップが当たった点には掛けない(直交と同じ優先関係)。等測グリッド中の扱いは
   直交と揃え、刻みの基準軸は変えない。
5. **スナップの追加と優先度**(タスク85〜87): 端点 > 交点 > 中点 > 中心 = 四半円点 > 垂線 = 接線 >
   仮想交点 > 近接点 > グリッド。
   - **種別ごとの ON/OFF** を足し `config.json` に保存する(`F3` は全体の切替のまま)。**近接点は
     既定 OFF**(常にどこかの線に当たり、グリッドや他の候補を潰すため)。他は既定 ON。
     UI は上部パネル(英語のまま。AGENTS.md の領域単位の規約)。
   - **垂線・接線は基点が要る**: 基点(`ortho_origin()`)から線分(ポリラインの辺)への垂線の足、
     円・円弧への接点。基点の無い段階・ツールでは候補を出さない。垂線の足は線分上(延長上は
     出さない)、接点は円弧の範囲内だけ。
   - **仮想交点**: 線分・ポリラインの辺の**延長どうし**、および延長と円(円弧は円として)の交点。
     候補の絞り込みは「無限直線(円)がカーソルから探索半径以内を通るもの」だけで無損失
     (交点がカーソルから半径以内なら、その交点を通る両方の直線も半径以内を通る)。実交点は
     交点スナップが先に拾うので重複は優先度で解ける。マーカーは延長部分を点線で示す。
   - 表・寸法はこれまでどおりスナップ源にしない。
6. **面取り**(タスク88): 線分どうし、2 距離(既定は等距離)。`mcad_geom` に `chamfer_lines` を
   `fillet_lines` と同じ契約(クリック位置で残す側を決める・結果は元の線の短縮 + 面の線分)で足す。
   キーは `Shift+F`(フィレット `F` と同系)。距離は上部パネルの入力欄。1 操作 = `Batch` 1 つ。
7. **矩形・正多角形**(タスク89): いずれも閉じたポリラインを作る(新しい幾何は足さない)。
   矩形 = `Shift+P`(2 隅。数値入力の `@w,h` で寸法指定)。正多角形 = `Shift+C`(中心 → 頂点、
   `Tab` で 内接/外接 を切替、辺数は上部パネル、3〜64)。
8. **結合・分解**(タスク90、選択モードの操作): 結合 = `J`、分解 = `Shift+J`。
   - 結合: 選択した線分・ポリラインが端点どうし(`mcad_geom::EPS`)で 1 本の鎖になるときだけ
     1 本のポリラインにする(輪になれば閉じる)。分岐・離れた図形・円弧を含む選択、**レイヤーか
     スタイルが混ざる選択は拒否**してステータスへ出す(どれかに黙って揃えない)。
   - 分解: ポリライン → 辺ごとの線分(レイヤー・スタイルを引き継ぐ)。他の種類は対象外として無視し、
     対象が無ければステータスへ出す。いずれも `Batch` 1 つ(undo 1 回)。

   **実装時追記(タスク90、2026-09-27)**:
   - **端点一致判定は `mcad_geom::point_tol`(`EPS` を両端点のスケールで相対化したもの)を使う**
     (`chamfer`/`split`/`trim_extend` が端点近接判定に使っている道具立てと同じ。絶対 `EPS` 直比較は
     座標スケールに弱いため採らない。設計判断本文の「`mcad_geom::EPS`」はこの相対化込みの意味)。
   - **頂点順の決定性**: 出力は**先頭 piece(選択順の1つ目)の向きをそのまま基準**にする。まず
     先頭 piece の点列を結果へ置き、その終端から未使用 piece を選択順で探して前へ伸ばし(見つから
     なくなるまで)、続けて先頭 piece の始端から同様に後ろへ伸ばす。輪になる場合は終端側の伸長中に
     先頭点へ戻って閉じる(この場合は始端側の伸長を行わない)。同じ選択・同じ順序なら常に同じ頂点列
     になる(`mcad_geom::join::join_chain` の doc・`crates/mcad-geom/src/join.rs`)。
   - **輪になる条件**: 全端点の次数がちょうど 2(次数 3 以上は分岐として拒否)。連結点の頂点は
     1 つにまとめ、座標は**先に結果へ入った piece の端点**を採用する(後から連結する piece 側の
     重複端点は捨てる)。共線の連続頂点はまとめない(形状を変えないため)。輪になった結果が頂点 3
     未満(例: 同じ2点を結ぶ線分2本)は `JoinError::DegenerateResult` で拒否する。
   - **零長の扱い**: piece 自体の実質長さ 0(`point_tol` 以下)は `JoinError::DegeneratePiece` で
     拒否する(結合側)。分解側は逆に、core の `Shape::Line::validate` は零長を拒否しない
     (`validate_accepts_degenerate_but_finite_shapes` で確認済み)が、**無意味な線分を増やさない
     ため app 層(`SelectTool::explode_command`)が実質長さ 0(`point_tol` 以下)の辺を作らずに
     捨てる**。全辺が零長のポリラインは分解せず、対象外として選択に残す(消えるだけになるのを防ぐ)。
   - **選択の後処理**: 結合成功後は選択を新しいポリライン1つに置き換える(`NewIds.entities`、
     要素は常に1個)。分解は「分解しなかった選択エンティティ(ポリライン以外)」+「新しく増えた
     線分(`NewIds.entities`、コマンド順)」を新しい選択にする(ポリライン以外は削除も変更もせず
     選択に残す)。選択に対象(ポリライン)が1つも無ければ `None` を返しステータスへ「Select a
     polyline to explode」を出す。
   - **拒否理由とステータス文言**は app 層の `tool::JoinReject`(`Display` で英語メッセージを持つ)
     に集約した。理由は 4 種: 選択2未満・対象外幾何混在(円弧/円/閉ポリライン/点/テキスト/寸法/表)・
     レイヤーかスタイル不一致・鎖として不成立(`mcad_geom::JoinError` を包む)。
9. **構築線**(タスク91): `EntityGeom::XLine { base, dir }`(`dir` は単位ベクトル、非有限・零は
   `validate` で拒否)。キー `Shift+L`(基点 → 通過点の 2 クリック)。
   - 描画はビューポートで、**SVG/PDF 出力は用紙の範囲で**切って描く(2026-09-23 ユーザー確定。
     出したくなければレイヤーを非表示にする)。DXF は `XLINE` で書き、`XLINE` を読む。
   - スナップ: 他の図形との交点・構築線どうしの交点を出す(構築線の主用途)。端点・中点は無い。
     移動・回転・ミラー・複製は効く。トリム・延長・オフセット・フィレットの対象外。
   - **有限の AABB を前提にしている箇所**(ズームフィット・矩形選択・カリング・`EntityGeom::aabb`
     の契約)の扱いは、tcad を壊さない形でタスク91 の着手時に決めて本節へ追記する
     (例: ズームフィットは基点だけを含める、矩形選択は線がボックスと交われば選ぶ)。

   **着手時の決定(タスク91、2026-09-27、采配役)**:
   - **`EntityGeom::aabb` の契約**: 戻り値の型(`Aabb`、`Option` でない)は変えない。`XLine` は
     **基点 1 点の退化した箱**を返し、doc に「無限長は表さない。表示上の範囲判定は app 層が直線として
     扱う」と書く。tcad は `Shape::aabb` しか使わず(`std_pack.rs`)、`EntityGeom` は `as_shape()` 経由で
     扱うので影響しない(`XLine` は `as_shape()` が `None`)。
   - **ズームフィット**(`document_aabb`): 上の箱のまま = 基点だけを含める(例示どおり)。
   - **カリング**(`entities_in_draw_order`): 箱では判定しない。表示範囲の矩形と直線が交わるかで判定する
     (基点が画面外でも線が画面を横切れば描く)。
   - **矩形選択**(`SelectTool::on_drag_end`): **基点が矩形に含まれれば選ぶ**(例示の「交われば選ぶ」は
     採らない)。既存の矩形選択は完全内包で、構築線は図面全体を横切るため「交われば選ぶ」だと
     輪郭線を囲うたびに構築線も選ばれてしまう。基点の内包ならズームフィットと同じ規則で済む。
     クリック選択は直線への距離で拾う。
   - **ピック**: 無限直線への垂直距離。**スナップの前段絞り込み**(`snap.rs` の `aabb().intersects(cursor_box)`)
     は構築線を箱で落とさず、直線とカーソル箱の交差で判定する。
   - **画面描画**: 表示範囲(余白付き)で切った線分として描く。**SVG/PDF** は用紙の範囲で切った線分で
     出す(用紙と交わらなければ出さない)。
   - **スナップ**: 構築線と他の図形(線分・円・円弧・ポリラインの辺・構築線)の交点を「交点」として出す。
     端点・中点・四半円点は無い。近接点・垂線の足は出してよい(無限直線への射影)。仮想交点の
     走査対象にはしない(もともと延長しているため、交点で足りる)。
   - **作図ツール** `Shift+L`: 1 クリック目 = 基点、2 クリック目 = 通過点(基点と同じ点は拒否)。
     2 点目には線分ツールと同じく数値入力・直交・極トラッキング・スナップが効く(`ortho_origin` = 基点)。
     連続作図は基点を保って次の通過点を待つ(AutoCAD の XLINE と同じ。`Esc` で基点からやり直し)。
     **既存の `L` は Shift を見ていないので `!shift` のガードを足す**。
   - **`dir` の不変条件**: 保存値は単位ベクトル。`validate` は非有限・零・長さが 1 から外れたもの
     (許容 1e-9)を拒否し、生成側(ツール・変換・DXF 読込)が正規化してから作る。回転・鏡映後も正規化する。
     `dir` と `-dir` は同じ直線だが、正規化の向きは揃えない(保存値をそのまま往復させる)。
   - **対象外の操作**: フィレット・面取り・結合・分解は構築線を選んだ場合に既存の「対象外」経路で拒否する
     (`as_shape()` が `None` なので自然に拒否される)。グリップは持たせない(現状グリップは寸法だけ)。
   - **スモークテスト後の変更(2026-09-27 ユーザー確定)**:
     - **トリム `X`・延長 `E` の境界に構築線を使える**(構築線で線分等を切る・構築線まで延ばす)。構築線
       **自体を対象にして切る・分割することはしない**(半直線が要るため。設計判断10 の `RAY` non-goal のまま)。
       分割 `B` は対象と構築線の交点へのスナップで足りる(下の実装時追記)。
     - **オフセット `O` を構築線に効かせる。結果は有限の線分**(仕様見直しのうえ 2026-09-27 ユーザー確定):
       操作は既存のオフセットと同じ(通過点クリック、または距離入力のあと向きを決めるクリック)。平行な直線
       L' 上にクリック点を射影した点 p をとり、L' と他の構築線(平行なものは交点なし)・可視レイヤーの形状
       (線分・円・円弧・ポリライン)との交点を集める(寸法・文字・表は含めない。スナップの対象と揃える)。
       **p を挟む最も近い交点 2 つ**の間を線分にする。片側に交点が無ければ、その側の端は L' が**用紙の範囲**
       (ワールド座標へ換算。SVG/PDF の切り取りと同じ用紙)と交わる点にする。両側とも決まらない(交点が無く

#### 表の編集と部品表レイアウトの要望(2026-09-23、タスク82 のスモークテスト時のユーザー要望)

要望は 5 点: (1) 「表を編集」ダイアログの広さを変えたい (2) 行高さ・文字高さの入力欄が広すぎる
(3) 行・列の追加・削除を最上段・右端だけでなく途中にも (4) 部品表の編集は部品の記入に集中したいので、
「行を追加」「削除」だけにし、列の追加・削除・行高さ・文字高さ・列幅は別の設定画面へ移す。あわせて

  はみ出すなら左・上へ回す。2 行目に書式のヒント)。キーは `route_keys` が 1 フレーム分の `egui::Event` 列から
  取り除く(egui の `key_pressed` はイベント列を数えるので、取り除いたキーは下流のどのショートカットにも見えない)。
  `TextEdit` にしない理由: フォーカスを持たせると、開いた瞬間の 1 文字目(フォーカスの無い状態で届いた文字)の受け渡し・
  キャンバスのクリックでのフォーカス喪失・`Enter`/`Esc` の `handle_tool_input` との取り合い、の 3 点をそれぞれ別に
  扱う必要がある(実機では試していない。キーを 1 か所で扱う方が単純でヘッドレスのテストにも載るため)。
- **書式の細部**: 数値は `[+-]? (数字列 [. 数字列?] | . 数字列)` だけを受ける(指数表記・`inf`・`nan` は書式の誤り。
  Rust の `f64::from_str` が受ける綴りを入れない)。**空白は文字列全体の前後だけ無視し、中の空白は位置に関わらず誤り**
  (数値の中・区切り(`,`・`<`)の周り・`@` の直後のいずれも。当初は区切りの周りと `@` の直後も無視していたが、貼り付けた
  `@1\n,2` が制御文字を空白に置き換えた `@1 ,2` として通ってしまうため、Codex 再レビュー [high] 指摘への対応で改めた。
  2026-09-25。入力中のパンや貼り付けの崩れで混ざった空白を黙って読み飛ばさない)。**`@L<A` も `L<A` と同じに受ける**(AutoCAD の相対極座標の綴り。どちらも基点から)。**`@` 単独は
  誤り**(AutoCAD の「直前の点」= `@0,0` は採らない。基点へ打ち戻すだけで退化形状しか作らないため)。負の長さは
  逆向き(`-10<0` = `10<180`)。角度は `[0, 360)` へ正規化し、**90° の倍数は厳密な軸方向**にする(`100<90` が
  `(6e-15, 100)` にならない。`ortho::RECT_AXES` を単位ベクトルで持つのと同じ理由)。桁あふれ(数値または結果の
  座標が有限でない)は拒否。判定順は 書式 → 基点 → 方向 → 有限性(`@abc` は基点が無くても書式の誤り)。
  ステータスバーの文言は `NumericInputError::message`(英語)。
- **基点は新しい拡張点 `Tool::numeric_input_base()`(既定 = `ortho_origin()`)**。円・アイソメ円だけが中心を返す。
  「基点は `ortho_origin()`」(着手前に確認した事実)のままだと、円・アイソメ円は `ortho_origin` を override して
  いないので 2 点目で `L`(= 半径)も `@dx,dy` も使えない。かといって `ortho_origin` を override すると、直交モード中の
  円の半径が軸への射影長に変わってしまう(既存の挙動の変更)ため、別の拡張点にした。点ツールは基点を持たない
  (絶対座標だけ)。受け付けるかは `Tool::accepts_numeric_input()`(既定 `false`)で、点・線分・円・円弧・アイソメ円・
  ポリラインの 6 つが `true`。矩形・正多角形・構築線(タスク89・91)はこれを override するだけで乗る(基点が
  `ortho_origin` と違えば `numeric_input_base` も)。
- **移動・複製**: `SelectTool::numeric_input_kind()`(移動・複製の配置中だけ `Some`)と `SelectTool::numeric_input_base()`
  (1 クリック目の基準点。基準点待ちの間は `None` で絶対座標だけ)。回転・鏡映は対象外のまま(数字キーは従来どおり)。
  打った点の確定では、ゼロ変位のしきい値にピック許容量(`PICK_TOLERANCE_PX / zoom`、画面基準)ではなく
  `DIM_DEGENERATE_EPSILON` を渡す。打った値は画面の大きさと無関係で、縮小表示中に `@1,0` のような小さな移動が
  「Zero displacement」として捨てられるため。
- **`L`(長さのみ)の方向 = いまツールがラバーバンドを引いている先 − 基点**(スナップ > 直交 > 素のカーソルの順で
  決まった点。`resolve_click_point` の結果)。したがって**直交モード中は直交で倒した方向**、スナップが当たっていれば
  スナップ点への方向になる(見えている線の向きに長さを取る。AutoCAD の直接距離入力と同じ)。移動・複製の配置は従来
  どおり直交を掛けないので、スナップ後の点への方向。ポインタがキャンバスを外れても最後の位置を覚えている。
  `resolve_point` は方向を引数で受けるので、**タスク84 は極トラッキングをこの「ラバーバンドの先」の決定
  (`resolve_click_point` 近傍)に差し込めば `L` の方向にもそのまま反映される**。方向が定まらない(カーソルが基点に
  重なる)ときは拒否。
- **キーの振り分け**(`route_keys`、`McadApp::ui` の冒頭で他のショートカットより先に呼ぶ):
  - イベントは届いた順に扱う。開くきっかけは、先頭の文字が `0`〜`9`・`.`・`-`・`@`(全角は半角へ寄せて判定)の最初の
    `Event::Text`。**開くのはその文字を生んだキー押下から**で、それより前に同じフレームで届いたイベント(`L` の押下と
    文字 `l` 等)は開く前の入力として手を付けずに下流へ残す(欄には入れない)。開始キーは `opening_key_index`: 文字
    イベントから後ろへ最初の押下キー(`@` は `Shift+2` 等でキーと文字の名前が一致しないため、名前ではなく直前の押下で
    対応付ける)。押下キーより先に別の文字イベントに当たれば、開始の文字にはキーが付いていない(IME 等)とみなし文字
    イベントから開く。開始キー(`1` の `Key::Num1` 等)は取り除くので、点ツールへは切り替わらない。当初はフレームの
    全イベントを開いた状態として扱っていたため、同じフレームで先に押した `L` のツール切替が失われた(Codex 再レビュー
    [medium] 指摘を采配役が採用、2026-09-25)。
  - 開いている間: **打った文字・貼り付けた文字列は捨てずにそのまま入る**(`to_half_width` で全角の ASCII を半角へ、
    U+2212 を `-` へ寄せるだけ)。**制御文字(貼り付けに混ざる改行・タブ等)は空白 `' '` に置き換える**(1 文字ずつ。
    `\r\n` は空白 2 つ)。捨てると貼り付けた `1\n2`・`1\t2` が `12` として確定するため(Codex 再レビュー [high] 指摘。
    前回の「制御文字だけは捨てる」を改めた、2026-09-25)。空白なら欄に見え、中にあれば `parse` が拒否し、末尾の改行
    (`100\n` の貼り付け)は前後の空白として通る。書式に合うかは確定時の
    `parse` が判定し、書式外の文字(`1e3` の `e`・貼り付けた `@1foo,2` の `foo`)は欄に見えたまま書式の誤りとして
    拒否され、`Backspace` で直せる。当初は許可外の文字を黙って捨てていたが、`1e3` → `13`・`1 2` → `12`・`@1foo,2` →
    `@1,2` のように打った値と違う点で確定するため改めた(Codex adversarial review [high] 指摘を采配役が採用、
    2026-09-25)。**空白も残す**: 入力中に `Space`(パンの修飾キー)を押すと空白が混ざるが、欄に見えており、数値の中の
    空白(`1 2`)は `parse` が拒否するので黙って別の値にはならない(前後の空白は `parse` の trim で許す)。
    `Backspace` で 1 文字消す(選択モードの削除へは届かない)。`Tab` とファンクションキー(`F3`・`F5`・`F8`・`F9`)は
    残す。**`Ctrl`/`Cmd` 併用の押下は取り除く**(`Ctrl+Z`・`Ctrl+N`・`Ctrl+O` 等を入力中に効かせない。`Ctrl+Enter`・
    `Ctrl+Backspace` も何もしない)。それ以外の押下(文字キー・`Delete`・`Home`・矢印・`Space` の押下イベント)も
    取り除く。
  - `Enter` は空なら**閉じてイベントを残す**(下流の従来の `Confirm` になる = 空の `Enter` は従来どおり)。空でなければ
    **そこでフレームの処理を打ち切って確定する**: 確定する文字列は `Enter` の時点のもの。同じフレームでそれより後に
    届いたキーボードのイベント(キー・文字・貼り付け・コピー/切り取り・IME)は捨てずに `NumericInputState::pending` に
    保留し、次のフレームの先頭へ戻して到着順に処理する(`restore_pending`。確定して閉じた欄の後なら通常の入力として
    ツール・ショートカットへ、数字なら新しい欄を開く、確定に失敗して欄が開いたままならその欄へ)。キーボード以外の
    イベント(ポインタ等)はそのフレームに残す(egui がフレームの開始時に状態へ反映済みで、戻しても意味が無いため)。
    当初は `Enter` の後も同じフレームの残りを処理していたため、`[1, Enter, 2]` が `12` で確定し、`[1, Enter, Esc]` は
    閉じた欄に空文字が残って解決に失敗し `Esc` もツールへ届かなかった(Codex 3 回目のレビュー [medium] 指摘を采配役が
    採用、2026-09-25)。
  - 保留の戻し方: `McadApp::route_numeric_input` が毎フレーム最初に、**そのフレームの状況(受け手・モーダル・テキスト欄の
    フォーカス)を判定してから、範囲を絞って戻す**(`numeric_input::PendingReplay::for_frame`。戻さなかった分は捨て、後の
    フレームにも出さない)。

      移動を始める。

        以上から、押下以外の経路は判定に足していない(ユーザー選択の範囲のまま)。

- **Codex adversarial review [high] への対応（2026-09-26、采配役の決定を implement-sonnet
  が実装）**: `collect_virtual_intersections` が「無限直線がカーソルから半径内を通る」線要素を
  **全部集めて総当たり**するため、カーソルの行・列上に同一直線の線分が数千本ある図面
  （例: 同じ y=0 上に短い線分が5000本）では毎マウス移動で数百万ペアの計算になり、既定 ON の
  まま線の多い図面を開くだけで固まる、との指摘。対応は以下のとおり。
  - **同一直線上の線要素を1本の「支持直線」（`LineGroup`）へまとめる**（`group_collinear_lines`、
    純関数）。**2段階**でまとめる（初回実装は角度・距離を1回の比較でまとめる単段だったが、
    Codex adversarial review [high] の**再指摘**（2026-09-26）を受けて2段階へ改めた。
    詳細は下の「2段階化への修正」参照）:
    1. **角度クラスタ化**: 各線分を「方向角（`y > 0`、または `y = 0` かつ `x > 0` になるよう
       正規化した向きの角度、範囲 `[0, π)`）」だけでソートし、クラスタの最初のメンバー
       （代表）を基準に隣接比較でクラスタ化する（直前要素との連鎖比較だと閾値以下の差が
       積み重なって実際には閾値を超える2線分が同じクラスタに入りかねないため、常に
       代表基準で比較する）。**`0` と `π` の境界は同じ角度として扱う**: ソート後の
       最初のクラスタ（`0` 付近）と最後のクラスタ（`π` 付近）の角度差が許容量以内なら
       1つに統合する。
    2. **距離クラスタ化**: 各角度クラスタの中で、原点からの符号付き距離でソートし、
       やはり代表基準でクラスタ化する（＝最終的な `LineGroup`）。**距離は角度クラスタの
       代表（最初のメンバー）の法線を使って全メンバー分を計算し直す**（メンバーごとに
       個別計算した法線のわずかな違いに左右されないようにするため）。
    - **角度の許容量は `mcad_geom::EPS`**（ラジアンは無次元なので直接比較する、`lib.rs` の
      許容量ポリシーどおり）。
    - **距離の許容量は `mcad_geom::rel_tol`**（座標スケールに対する相対許容量。
      `mcad_geom::line_line_intersection` の平行判定〔`EPS * |r| * |s|`〕と桁数が矛盾しないよう、
      同じ `EPS` を核にした相対許容量に揃えた）。
    - 交点計算はグループの代表線分どうし・代表と円で行う。実体上の判定
      （`group_contains_point`）は「グループ内の**いずれか**のメンバー線分の区間内
      〔`t ∈ [0,1]`、`EPS` 境界許容〕に交点があれば実体上」とする。ガイドの `from`
      （`nearest_group_endpoint`）は、実体上でない側ではグループの**全メンバー**の端点のうち
      交点に最も近いものを選ぶ（最初に見つかったメンバーの端点に固定しない）。
    - 円要素は同じ中心・半径をまとめる処理を追加していない（円どうしは組にしないため、
      線×円は O(グループ数 × 円要素数) に収まり、下記の組の数の予算だけで十分に
      抑えられる）。
  - **2段階化への修正（Codex adversarial review [high] 再指摘、2026-09-26）**: 初回実装は
    「角度・距離の組」を1回のソート・1回の隣接比較でまとめていたため、回転・鏡映を経た図形
    のように角度に `1e-16` 程度の浮動小数の揺れがあると、同一直線上の線分と別の平行線の線分が
    角度順で交互に並び、代表基準の隣接比較ではまとまらず線分ごとに別グループへ分かれてしまう
    不具合があった。特に `0` と `π` の境界（例: 方向 `(1, -1e-17)` は正規化で `y` の符号が
    反転し `π` 側になる）で同じ直線が2つに割れ、行に大量の線分がある図面では上限
    （`VIRTUAL_INTERSECTION_MAX_LINES`）による切り詰めで本当に必要な交差相手（列側）の直線が
    落ち、仮想交点が消える事態になりうる、との指摘。上記の2段階（角度→距離、`0`/`π` 境界の
    統合、距離はクラスタ代表の法線で再計算）へ改めて解消した。上限で切り詰める前に各グループの
    カーソルとの距離でソートする処理自体は変更していない。

      表現し、各線分の角度を `1e-15` 程度ずつ交互に揺らしても、グループ数が2（各200本）に
      なること（`group_collinear_lines_merges_angle_wobble_across_two_parallel_rows`）。

    - **平行なグループ（同じ角度クラスタ）どうしは組にしない**: `LineGroup` に
      [`group_collinear_lines`] の段階1で採番した角度クラスタ番号

      作る。ハッチングのような平行線がいくらあっても組の数を増やさない。

      `VIRTUAL_INTERSECTION_MAX_LINE_PAIRS = 4096`（線×線）・
      `VIRTUAL_INTERSECTION_MAX_LINE_CIRCLE_PAIRS = 4096`（線×円）。線グループ・
      円要素はどちらもカーソルとの距離で昇順に並べ、組は「距離順の添字 `i` の昇順・
      各 `i` に対し `j < i` の昇順」で処理する（先に処理される組ほど両方がカーソルに
      近い）。組を1つ計算するたびに数え、予算に達したら打ち切る。

      当初は単一の共有予算（`VIRTUAL_INTERSECTION_MAX_PAIRS`）を線×線・線×円で
      共有し、線×線を先に処理していたため、**非平行の線グループが約92本

      線×円が1組も調べられなくなる**（有効な線×円の仮想交点が消える）欠陥が
      あった。線×線・線×円をそれぞれ独立のカウンタ・独立の予算にし、線×線の
      消費状況に関係なく線×円の組が必ず一定数まで調べられるようにした。

      場合（放射状に数十本以上の直線が数ピクセル内を通る図面）に限り、予算を

      増えるため、予算の無い無損失な方式は取らない。**実交点

#### 検収基準(M12完了の定義)

- `K` が「部品表を使う」ON の図面で部品表が無ければ部品表(見出し + 3 行)を表題欄の直上へ即時に置き、
  それ以外では表を置く。部品表は 1 図面に 1 つで、2 つ目を作る操作(`K`・複製・
  手編集ファイルの読込)はすべて拒否される。v7 以前の図面を開いても表の中身・種類は変わらない
- 作図中に `x,y`・`@dx,dy`・`L<A`・`L` で点を指定でき、解釈が headless テストで固定されている
- 極トラッキング・四半円点・近接点・垂線・接線・仮想交点が使え、種別ごとに ON/OFF でき設定が残る
- 面取り・矩形・正多角形・結合・分解が 1 操作 = undo 1 回で動き、拒否すべき入力を拒否する
- 構築線が作図・移動でき、画面と SVG/PDF(用紙で切る)に描かれ、DXF `XLINE` で往復する
- 表の列ごとの揃えが画面・SVG/PDF・DXF で同じに出て、部品表は 部番・個数・材質・質量 が中央揃えになる。
  「表を編集」は広さを変えられ、途中の行・列を挿入・削除でき、部品表では記入と部品行の追加・削除だけを出す
- `.mcad` v7 以前の読込が無損失(fixture)、v8 往復が無損失
- `../tcad` の `cargo test --workspace` 通過、fmt / clippy / test 通過、GUI 変更は手動スモークテストを記録する

**→ 全項目 v0.12.0 で達成済み(2026-09-27、タスク81〜94完了)。手動スモークテストは各タスクの記録を参照。**
