### M13: 幾何拘束ソルバー(v0.13.0)の設計(2026-09-27 詳細設計、実装完了)

範囲は 7章「マイルストーン一覧」表の M13 行。本節はそれを実装可能な粒度へ落とす。骨格の 6 点
(下記「ユーザー確定事項」)は 2026-09-27 ユーザー確定、それ以外の細部は采配役が決めた。

#### ユーザー確定事項(2026-09-27)

- **永続拘束**: 拘束は図面に保存し(`.mcad` v9)、図形を編集するたびにソルバーが満たし直す。
  「その場で形を合わせるだけで保存しない」一回適用の案は採らない。
- **拘束は寸法と別**: 距離拘束は寸法エンティティと独立したオブジェクトとし、寸法は従来どおりの注記。
  **駆動寸法(寸法値を変えると形が動く)は M13 の範囲外**(寸法と図形の関連付けが無いため、関連付けの
  設計から要る。M13 の後に回す)。
- **拘束の種類**: 最小セット(水平・垂直・一致・距離)に、平行・直交・等長・等半径・固定・接線・
  半径・角度を加える。
- **対象の図形は線分・円・円弧**。ポリラインは対象外(頂点の追加・削除・結合・分解で頂点の番号が
  変わり、拘束が指す先が壊れるため)。拘束したいときは分解して使う。点・構築線・文字・寸法・表も対象外。
- **図形のグリップ編集を M13 に含める**: 線分の端点、円・円弧の中心と半径、円弧の端点をドラッグ
  できるようにする。ドラッグ中は拘束を解きながらプレビューし、離した時点で確定する(undo 1 回)。
  拘束の無い図面でも使える。
- **拘束を付けたときに動くのは後に選んだ図形**(AutoCAD と同じ慣習)。最初に選んだ図形を止めたままでは
  満たせないときに限り、両方を動かす。

#### 着手前に確認した事実(2026-09-27、采配役がコードで確認)

- `mcad-geom` の依存は `serde` だけ(`crates/mcad-geom/Cargo.toml`)。
- `Arc` は `center`・`radius`・`start_angle`・`end_angle`(ラジアン、開始角から CCW)、`Circle` は
  `center`・`radius`。
- グリップ編集は寸法だけにある(`dim_grip_hit`・`SelectTool::start_grip_drag`、main.rs)。図形の
  グリップは無い。
- tcad は `mcad_core::Command` を組み立てているが、網羅 `match` はしていない(`../tcad` を grep で確認)。
  `Command` は `#[non_exhaustive]` ではないため、tcad が今後 `match` を書くとバリアントの追加で壊れる。
  **M13 で足す `Command` のバリアントは既存の tcad を壊さない**。
- `.mcad` のエンティティは配列で保存し(`FORMAT_VERSION = 8`)、読込時に `Command` で組み立て直して
  ID を新しく振る。拘束がエンティティを指すには、ファイル上では配列の添字を使う必要がある。
- undo 履歴は `Applied` の逆操作記録(document.rs)。1 回の `apply` が 1 つの `HistoryEntry` になる。

#### 設計判断

1. **ソルバー本体は `mcad-geom` に置き、エンティティを知らない汎用の非線形方程式ソルバーにする**
   (タスク95)。新モジュール `mcad_geom::solve`。入力は「パラメータのベクトル・固定するパラメータの
   集合・残差とその解析的ヤコビアンを返す方程式の集まり」、出力は解いた後のパラメータまたはエラー
   (収束しない・満たせない)。`EntityId` や `Constraint` は mcad-core 側で扱い、geom は知らない
   (依存方向の不変条件と、7章 M13 行の「mcad-geom を GUI 非依存に保った布石の回収」)。
   - **解法は最小ノルム型の減衰ガウス・ニュートン法**: 1 反復の更新量を
     `Δx = −Jᵀ (J Jᵀ + λI)⁻¹ f` とする(Levenberg–Marquardt の減衰つき)。拘束が足りない(自由度が
     残る)系では、満たすための動きが最小になる解を選ぶ — 「編集していない図形はできるだけ動かさない」
     という CAD として自然な振る舞いになる。
   - **反復の受理規則**(2026-09-27 Codex adversarial review 3回目指摘2 を反映。更新式だけでは減衰係数の
     決め方も悪化したステップの扱いも決まらず、LM 法にならない):
     - 目的関数は `F(x) = ½ Σ (fᵢ(x) / tolᵢ)²`(`tolᵢ` は下記の方程式ごとの許容値)。パラメータは
       角度の重みづけ(下記)をした尺度で扱い、更新量の最小ノルムもこの尺度で測る。
     - 開始時に残差とヤコビアンがすべて有限であることを確かめる。有限でなければ解かずに `Err`。
     - 試行ステップ `x' = x + Δx` を作り、`F(x')` とその残差がすべて有限で、かつ `F(x') < F(x)` の
       ときだけ受理して `x ← x'`・`λ ← max(λ / 10, λ_MIN)`。それ以外は `x` をそのまま残し
       (棄却 = 状態を変えない)、`λ ← λ × 10`。途中の反復で線分の長さや半径が `ATOL_LEN` を
       下回った `x'` も棄却する(ヤコビアンの分母が 0 に近づくのを防ぐ)。
     - `λ` の初期値は `max(λ₀ × max(diag(J Jᵀ)), λ_MIN)`(`J` は行を許容値で割ったもの)。**`λ_MIN > 0`
       なので `J Jᵀ + λI` は常に正則**(2026-09-27 Codex adversarial review 4回目指摘1 を反映: 下限が
       無いと、自由なパラメータが無い系で `J Jᵀ` と `λ` がともに 0 になり、逆行列が取れない)。
     - **自由なパラメータが無い系の早期判定**: 固定集合を除いた自由なパラメータが 0 個で、割った残差の
       最大値が 1 を超えるなら、反復せずに「固定された図形では拘束を満たせない」`Err` を返す(判断3 の
       例: 水平拘束のついた線分を単独で回転した場合がこれに当たる)。自由なパラメータはあるが残差を
       減らす方向が無い系は、`Δx` が 0 になって `F` が減らず、棄却が続いて `λ` が `λ_MAX` を超え、
       停滞として決定的に失敗する。
     - **成功**: 割った残差の最大値が 1 以下(収束判定)。**失敗**: 試行回数(受理と棄却の合計)が上限に
       達した、`λ` が `λ_MAX` を超えた(停滞)、のいずれか。失敗はすべて `Err` で、呼び出し側の
       ロールバックに任せる(ソルバー自身は入力のパラメータを書き換えない)。
     - **決定的に動く**: 乱数を使わず、方程式とパラメータの並び順は `ConstraintId` と `EntityId` の
       順に固定する。同じ入力からは同じ結果か同じ失敗になる。
     - 受理したステップでは `F` が必ず減る(単調減少)。解は現在の形から出発した局所解で、接線の側・
       外接/内接・角度の向きといった枝は判断2 で保存した符号で固定するため、別の枝へ飛び移らない。
     - 定数 `λ₀`・`λ_MIN`・`λ_MAX`・試行回数の上限は実装時に決めて実装時追記へ残す。
     - **テスト**(タスク95 の完了条件): 解から遠い初期値(移動量が図形の大きさの 100 倍程度)、
       接線の内接と外接、角度拘束の ±π 付近、階数が落ちる系(矛盾しない重複拘束)で、受理した
       ステップの `F` が単調に減ること・収束すること、解の無い系が上限で決定的に失敗すること、
       **自由なパラメータが 0 個で満たされていない系が反復せずに `Err` になること**。
   - **外部クレートは足さない**。系は連結成分ごとに分けて解くため、行列は小さい(1 成分で数十〜数百
     パラメータ程度)。密行列のガウス消去(部分ピボット)で足りる。数値線形代数のクレートを足すと
     tcad の依存にも入るため、必要が実測で示されるまで入れない。
   - **ヤコビアンは解析式で書き、テストで数値微分と照合する**(各方程式について中心差分との一致を
     proptest で確かめる)。
   - **許容値は方程式ごとに、残差の種類と拘束対象の局所寸法で決める**(2026-09-27 Codex adversarial
     review 指摘1 を反映。当初案の「座標の尺度に比例する単一の許容値」は、長さ・ラジアン・無次元の残差を
     同じ物差しで測るうえ、原点から遠い図面ほど角度の拘束まで緩む欠陥があった):
     - 方程式は**長さ型**(一致・距離・水平/垂直・点と線の距離・接線・等長・等半径・半径)と
       **角度型**(平行・直交は単位方向ベクトルの外積・内積で、ずれが小さいとき近似的にラジアン。
       角度は判断2の主値化した差のラジアン)に分ける。
     - 長さ型の許容値 = `max(RTOL × L, K × f64::EPSILON × C, ATOL_LEN)`。`L` は**拘束対象の代表長さ**
       で、**拘束が参照するすべてのエンティティ**(点を指す拘束では、その点を持つ線分・円・円弧)の
       大きさ(線分の長さ・円と円弧の半径)と、距離・半径拘束の値の最大。点どうしの一致のように
       拘束そのものが長さを持たなくても、点を持つ図形の大きさが入る。`C` は対象の点の座標の絶対値の
       最大。`C` の項は浮動小数の分解能の下限にだけ効き(原点から 1e6 mm でも 1e-9 mm 台)、それより
       粗い判定を座標の位置から持ち込まない。
     - **`ATOL_LEN` は許容値を必ず正にするための絶対下限**(2026-09-27 Codex adversarial review 2回目
       指摘1 を反映: 原点で一致する 2 点のように `L` と `C` がともに 0 になりうると、許容値 0 で行を
       割って 0/0 になる)。値は意味のある寸法より十分小さく取り(目安 1e-12 mm)、判定の粗さを
       決める役にはしない。ソルバーは各行の許容値が有限かつ正であることを確かめてから割る
       (満たさなければ解かずに `Err`)。
     - 角度型の許容値 = `ATOL_ANG`(ラジアンの絶対値。尺度に依存しない)。
     - ソルバーは各行を自分の許容値で割って解き(行の尺度をそろえる)、**収束は割った残差の最大値が
       1 以下**。`.mcad` 読込時の充足検査(判断5)も同じ判定を使う。
     - **許容値は求解の開始時に 1 回だけ計算して固定する**(2026-09-27 Codex adversarial review 7回目
       指摘を反映: 反復中に現在の形から計算し直すと、残差を減らさずに線分を伸ばして `L` を大きくする
       だけで割った残差が下がり、満たされていない形を収束と誤判定できる)。計算の元はコマンドを適用した
       直後・解く前の形と拘束の値で、反復中は変えず、ヤコビアンに許容値の微分は含めない。
       **成功の判定は、開始時の許容値と、解いた後の形から計算し直した許容値の両方で満たすこと**を
       条件にする(小さい方で判定する)。後者を入れるのは、`.mcad` 読込時の検査が保存された形から
       許容値を計算するため — 両方を満たした形だけを文書に入れれば、保存した図面は必ず読込検査を通る。
     - **テスト**(タスク95・97 の完了条件): 図形を 100 倍以上に伸ばせる自由度を持つ系で、実際の残差を
       減らさずに `L` を大きくするだけの経路が収束と判定されないこと。`apply` が受け付けた形を保存して
       読み込むと、必ず充足検査を通ること。
     - 定数 `RTOL`・`ATOL_ANG`・`K` と反復上限は実装時に決めて実装時追記へ残す(目安は 1e-9 前後)。
     - **テスト**(タスク95・97 の完了条件): 同じ形を原点と原点から 1e6 mm 離れた位置に置いたとき
       収束・拒否・読込可否の判定が一致すること、代表長さ 1e-3 mm と 1e5 mm の形がともに解けること、
       原点から遠い図面でも角度型の許容値が緩まないこと、**原点で一致する 2 点・すべての座標が 0 の
       点を含む拘束で許容値が正のまま NaN を出さないこと**。
     - 7章「随時対応」の「絶対 EPS の負債」は増やさない(退化判定を含め、M13 で足す判定は上記の
       相対・種類別の許容値を使う)。
   - **自由度** = 固定していないパラメータの数 − 解いた点でのヤコビアンの階数。階数はピボット付き
     消去で数える(右パネルの表示に使う。判断6)。
   - 角度のパラメータ(円弧の開始角・終了角)と長さのパラメータは単位が違うため、そのまま最小ノルムを
     取ると角度が動きやすい/動きにくいに偏る。**角度パラメータは半径で重みづけする**(弧長に揃える)
     方針とし、具体的な式は実装時に決めて実装時追記へ残す。
   - **実装時の設計方針追記(2026-09-27、タスク95)**: `mcad_geom::solve`(`crates/mcad-geom/src/solve.rs`)。
     - **公開 API**: `trait Equation`(1 本 = スカラー残差 1 つ。`params()` が依存パラメータの添字、
       `residual`・`gradient`・`kind(x) -> ResidualKind`)、`enum ResidualKind { Length { size, coord }, Angle }`
       (長さ型の `L`・`C` は方程式側が状態から計算する)、`struct Problem`(`params`・`fixed`・`weights`・
       `equations`・任意の `admissible` フック = 試行点の妥当性判定。退化の棄却に使う)、
       `solve(&Problem) -> Result<Solution, SolveError>`、`max_scaled_residual`・`is_satisfied`(その形で
       許容値を計算する充足検査。判断5 の読込検査用)、`degrees_of_freedom`、`check_jacobian`(中心差分の
       照合ヘルパー。刻みは `step·max(|x|,1)` なので座標 1〜1000 程度で使う)。`SolveError` は
       `InvalidInput`・`NonFinite`・`InvalidTolerance`・`NoFreeParameters`・`Stalled`・`TrialLimit`。
     - **定数**: `RTOL = 1e-9`・`ATOL_LEN = 1e-12` mm・`ATOL_ANG = 1e-9` rad・`K_ROUNDOFF = 16`・
       `LAMBDA_0 = 1e-3`・`LAMBDA_MIN = 1e-12`・`LAMBDA_MAX = 1e20`・`MAX_TRIALS = 200`(実測: 収束は
       5 回以下、解の無い系の停滞判定は 28〜110 回)・`RANK_RTOL = 1e-9`(列と行を最大絶対値 1 に正規化した後、
       完全ピボットのガウス消去で最大ピボットに対する相対閾値)。根拠は各定数の doc。
     - **自由度の階数は重みも許容値も使わずに数える**(Codex adversarial review(2026-09-27)指摘: 当初は列を
       重みで割ってから行だけを正規化し絶対閾値で判定していたため、角度の重み(半径)によって同じ拘束構造の
       自由度が図形の大きさで変わりえた)。列の尺度は階数を変えないため、素のヤコビアンを列・行の順に正規化し、
       完全ピボットで数える。重みを 1e-6〜1e6 に振っても、半径 1e-3〜1e5 の円弧でも自由度が一致することを
       回帰テストで確認。重みを使うのは最小ノルム更新だけ。
     - **λ は無次元の係数 `μ` と尺度 `s` の積にした**(上記「`λ` の初期値」の文面からの解釈変更):
       `λ = μ·s`、`s` は現在の点での `max(diag(J Jᵀ))`(0 なら 1)。`λ₀`・`λ_MIN`・`λ_MAX` は `μ` に対する
       値。`J` は `1/tol` に比例し `tol` が図形の大きさで桁ごと変わるため、`λ` の絶対値で上下限を置くと
       大きい系で下限が効かず小さい系で停滞判定が早すぎる。`s > 0` なので正則性は保たれる。
     - **自由なパラメータの早期判定は「固定されておらず、かつどれかの方程式が参照する」パラメータで
       数える**(上記の「自由なパラメータが 0 個」を含む広い条件。参照されないパラメータは残差を
       変えられない)。自由度の計算では参照されないパラメータも自由度に数える(水平拘束だけの線分 = 3)。
     - 受理条件に「試行点のヤコビアンと `J Jᵀ` が有限」を加えた。開始時の許容値では満たすが解いた後の
       許容値で満たさないときは反復を続ける。
     - 連結成分への分割はパラメータ単位ではエンティティ単位の用途に合わないため geom に置かず、
       タスク97(core)で行う。角度パラメータの重みは「求解開始時の半径」を doc で推奨(最終決定は
       タスク96・97)。
     - **既知の制約**: 原点から 1e6 mm 離れた位置では座標の分解能が約 1.2e-10 mm のため、長さ約 0.2 mm
       未満の線分では向きの分解能が `ATOL_ANG` より粗くなり、角度型の拘束が解けない(実測: 長さ 0.01 mm
       の線分の角度拘束は原点で解け、1e6 mm で `Stalled`)。「原点から遠い位置で判定が一致」と「微小な
       図形が解ける」はそれぞれ単独では満たすが、両方が重なる場合は満たさない。角度型の許容値に
       丸めの下限 `K·ε·C/ℓ` を入れれば解消できるが、判断1 の「角度型は尺度に依存しない」を変える
       ため採らない(実用図面で 1 km 先に 0.2 mm 未満の線分を置く場面は無いとみなす。2026-09-27 ユーザー承認)。
2. **拘束のデータモデルは mcad-core に置く**(タスク96)。`#[non_exhaustive] pub enum Constraint`、
   ID は `ConstraintId`(エンティティ・レイヤーと同じく `SlotMap` の `Option<T>` による墓標で、undo/redo を
   またいで ID が安定する)。点は `PointRef { entity: EntityId, kind: PointKind }`、
   `PointKind` は `Start`・`End`(線分・円弧)・`Center`(円・円弧)。
   | 拘束 | 対象 | 方程式(残差 = 0) |
   |---|---|---|
   | 一致 | 点・点 | x・y の差(2 本) |
   | 水平 / 垂直 | 線分 | 端点の y の差 / x の差 |
   | 距離 | 点・点 | `‖p−q‖ − d`(`d > 0`。線分の長さは同じ線分の始点・終点で表す) |
   | 距離 | 点・線分 | 点から線分を延長した直線までの符号付き距離 − `s·d`(`s` は作成時の側) |
   | 平行 / 直交 | 線分・線分 | 単位方向ベクトルの外積 / 内積 |
   | 等長 | 線分・線分 | 長さの差 |
   | 等半径 | 円・円弧の 2 つ | 半径の差 |
   | 半径 | 円・円弧 | `r − d` |
   | 角度 | 線分・線分 | 主値化した角度差(下記) |
   | 接線 | 線分・円/円弧 | 中心から直線への符号付き距離 − `s·r`(`s` は作成時の側) |
   | 接線 | 円/円弧・円/円弧 | 外接は `‖c1−c2‖ − (r1+r2)`、内接は `‖c1−c2‖ − s(r1−r2)`(`s` は作成時の大小。下記) |
   | 点の固定 | 点 | `p − p₀`(x・y の 2 本。`p₀` は作成時のワールド座標で、拘束に保存する) |
   | 図形の固定 | 線分・円・円弧 | その図形の全パラメータを固定集合へ入れる(方程式ではない) |
   - 値(距離・半径・角度)はワールド単位とラジアンで持ち、UI では mm と度で出す。
   - **角度の残差は主値化する**(2026-09-27 Codex adversarial review 指摘3 を反映): 線分 1・2 の方向
     ベクトル(始点 → 終点)を `d1`・`d2`、なす角を `φ = atan2(d1 × d2, d1 · d2)` とし、残差を
     `atan2(sin(φ − θ), cos(φ − θ))`(`(−π, π]` の値)とする。`φ` を直接 `θ` と引くと ±π をまたいだ
     瞬間に残差が 2π 跳ぶ。主値化した残差が不連続になるのは `φ − θ = ±π`(解から最も遠い形)だけで、
     解の近くでは滑らか。ヤコビアンは `∂φ` をそのまま使う(主値化は定数の 2π の差しか生まないため)。
     `θ` は作成時の `φ` を初期値にし、保存時に `(−π, π]` へ正規化する。平行は外積(反平行も平行として
     満たす)、直交は内積で、いずれも周期の問題を持たない。
     **テスト**(タスク96 の完了条件): ±π をまたぐ回転、`θ` が 0 と ±π の近く、反平行の線分で、
     残差の連続性・ヤコビアンの数値微分照合・収束を確かめる。
   - **値の範囲と特異点**(2026-09-27 Codex adversarial review 3回目指摘1 を反映。ノルムと `abs` は
     0 で微分できず、解析ヤコビアンが 0 除算になる):
     - **点どうしの距離は `d > 0` に限る**。0 にしたいときは一致拘束を使う(作成・値の変更で `d` が
       長さ型の許容値以下なら拒否し、ステータスバーで一致拘束を案内する)。点と線の距離は `d ≥ 0` を
       許す(符号付き距離は直線が退化しない限り滑らか)。半径は `d > 0`。
     - **ノルム `‖p−q‖` のヤコビアンは、`‖p−q‖` が `ATOL_LEN` 未満のとき固定の単位ベクトル `(1, 0)` を
       方向として使う**。`d > 0` の解はこの点に無いので、一致した 2 点から距離拘束を解き始めても
       0 除算にならず、x 方向へ離れて進む(決定的)。外接の中心間距離も同じ規則。
     - **内接は `abs(r1−r2)` を使わず、作成時に `s = sign(r1 − r2)` を保存して `s(r1−r2)` を目標に
       する**(`abs` の折れ目を消す)。作成時に `abs(r1 − r2)` が長さ型の許容値以下(等半径の内接 =
       同心で同じ円)なら作成を拒否し、解いた後に `s(r1−r2)` が許容値以下になった形は退化として
       拒否する(判断3)。等半径拘束と内接の組み合わせはこの規則で矛盾として拒否される。
     - 平行・直交・角度・点と線の距離・直線と円の接線は線分の単位方向ベクトルを使う。線分の長さは
       退化判定と反復の棄却規則(判断1)で `ATOL_LEN` 以上に保たれるため、0 除算は起きない。
     - **テスト**(タスク96 の完了条件): 一致した 2 点に距離拘束を足す、同心の円に外接を足す、等半径の
       円に内接を足す(拒否)、距離の値を 0 へ変える(拒否)で、NaN が出ないことと期待どおりの
       受理・拒否。
   - **点の固定は方程式、図形の固定は固定集合で表す**(2026-09-27 Codex adversarial review 5回目指摘を
     反映): 円弧の端点は独立したパラメータではなく `center + r(cos a, sin a)` から導かれるため、
     「点に対応するパラメータを固定集合へ入れる」では表せない(中心・半径・角度を全部止めると端点以外まで
     止まり、一部だけ止めると端点が動く)。そこで点の固定は、保存した座標 `p₀` との差を残差にする
     長さ型の方程式にし、ヤコビアンは円弧の中心・半径・該当する角度へ連鎖させる。線分の端点・中心の
     固定も同じ方程式で表し、書き分けない(実装を 1 通りにするため)。これにより、円弧の始点を固定した
     まま、中心・半径・終点が他の拘束に追従できる。自由度の計算(判断1)も方程式の階数として正しく
     数えられる。図形全体の固定だけが固定集合を使う。`.mcad` には `p₀` を保存する(判断5)。
     **テスト**(タスク96・97 の完了条件): 円弧の始点を固定し、半径拘束の値を変えると、始点は動かずに
     中心と終点が動くこと。点の固定を付けた円弧の自由度が 5 − 2 = 3 になること。保存・読込で `p₀` が
     往復すること。
   - **接線は「延長した直線・円弧を含む円」どうしの接線と定義する**(2026-09-27 Codex adversarial review
     6回目指摘を反映、同日ユーザー承認。指摘は、接点が円弧の掃引範囲や線分の区間の外にあっても残差が 0 になり、見た目には
     離れた図形が接線として保存されるというもの)。接点を区間内に収める条件は不等式で、等式だけを扱う
     判断1 のソルバーには入らない(不等式を扱うには有効制約法などの別の仕組みが要る)。そこで M13 では
     この定義を明示して受け入れ、次の 2 点で利用者に見えるようにする:
     - 接線の拘束記号は接点に描き、**接点が線分の区間・円弧の掃引範囲の外にあるときは、接点から図形の
       最寄りの端点までを破線でつないで**「延長上で接している」ことを示す(判断6)。
     - 右パネル「拘束」の一覧で、接点が区間外の接線に「(延長上)」と添える。
     区間内に接点を保つ接線(不等式拘束)はスコープ外。接点を図形の端点にそろえたいときは、接線に
     一致拘束を組み合わせる(フィレット形状の作り方)。
     **テスト**(タスク96・99 の完了条件): 接点が円弧の掃引範囲の外(±π をまたぐ掃引、内接・外接の両方)
     でも拘束は満たされ、区間外判定が正しく出ること。区間内判定は円弧の CCW 掃引で行う。
   - **側の符号 `s` は必ず ±1**(2026-09-27 Codex adversarial review 4回目指摘2 を反映: 中心が直線上に
     あると作成時の符号付き距離が 0 で側が決まらず、`s = 0` にすると中心を通る直線を接線として受け付けて
     しまう)。直線と円の接線・点と線の距離で、作成時の符号付き距離の絶対値が長さ型の許容値以下なら
     **`s = +1`(線分の始点 → 終点の向きに対して左側)に決める**。拒否にしないのは、中心を通る補助線を
     引いてから接線にする作図がふつうにあるため。決めた側へ向けて距離 `r`(または `d`)まで解く。
     外接/内接が作成時に同じ近さなら外接を選ぶ(同じく決定的にする)。
     **テスト**(タスク96・97 の完了条件): 中心を直線上に置いた円と直線に接線拘束を付けると、解いた後に
     中心から直線までの距離が半径に等しく、中心が左側にあること。
   - **符号・側・外接/内接は作成時の形から決めて保存する**: 解くたびに決め直すと、ほぼ接する形で
     反対側へ飛び移るため。
   - 円弧の端点は `center + r(cos a, sin a)` で表し、パラメータは中心・半径・開始角・終了角の 5 つ。
     線分は端点 2 つの 4 つ、円は 3 つ。
   - 平行・直交・角度・等長は線分どうしに限る(円弧の接線方向は範囲外)。
   - **実装時の設計方針追記(2026-10-03、タスク96)**: `crates/mcad-core/src/constraint.rs`(型・構造検証・
     コンストラクタ・接点・切り詰めの削除規則)、`constraint/equations.rs`(方程式と方程式系の組み立て。
     `pub(crate)`)、`document/constraints.rs`(読み取り API・連鎖削除・充足検査)。公開 API の一覧は
     `mcad-core` のクレート doc(`lib.rs` 冒頭)を一次情報とする。

     - **側と外接/内接は型で ±1 を保証する**: `Side { Left, Right }`、`CircleTangency { External,
       Internal(LargerCircle) }`。生の数値で持たないため、`s = 0` の拘束は作れない。
     - **同種 2 対象の拘束はフィールド順 = 選択順**(`a` が先、`b` が後)。**異種 2 対象(点と線の距離・線と円の
       接線)はフィールドが役割で決まり、選択順を持たない** — 「後に選んだ方を動かす」をこれらへどう渡すかは
       タスク97 で決める。
     - **96 では解かず、最も外側の `Document::apply` の最後に充足検査をする**(判断3 の「解くのは最も外側の

       満たさないものがあれば全体を巻き戻して `CoreError::ConstraintUnsatisfied`(`ConstraintId` 順で最初の

       拘束に反する `ModifyEntity` はすべて拒否になる。拘束でつながった図形を `Batch` でまとめて平行移動・
       回転する操作は通る。
     - **固定された図形の変更と、拘束が指せなくなる種類の変更は、サブコマンドの時点で拒否する**(ロック・
       部品表と同じ「その時点の状態」規則)。前者は `CoreError::EntityFixed`、後者は `InvalidConstraint`。
       幾何が変わらない差し替えは固定があっても no-op のまま。固定した図形の削除・スタイル変更は通る。
     - **構造検証**(`AddConstraint`・`SetConstraintValue` の実行前): 参照先の存在と種類、同じ対象の二重指定、
       値の有限性、点どうしの距離 `d` > 長さ型の許容値、点と線の距離 `d ≥ 0`、半径 > 0、内接は
       `s(r1−r2)` > 許容値。許容値はその拘束自身の方程式の `kind` から取り、別の式を持たない。角度は
       範囲外の値だけ主値化する(範囲内の値を `atan2` に通すと 1 ulp ずれ、同じ値の no-op 判定が崩れるため)。
       拘束の追加・削除・値変更そのものはレイヤーロックを見ない。
     - **方向を使う方程式(平行・直交・角度・点と線の距離・線と円の接線)は、線分の長さが `ATOL_LEN` 未満なら
       NaN を返す**(充足検査では未充足、`solve` では開始時 `NonFinite`)。方向 `(1, 0)` で有限値を返す案は、
       長さ 0 の線分が水平線と平行と判定されるため採らない。ノルム(点どうしの距離・中心間距離・等長)だけが
       上記の `(1, 0)` 規則を使う。

       反映: 長さ 0 の線分でも水平・垂直・等長は残差 0 になり、ソルバーが初期状態として使えない文書を
       作れた)。拘束が参照する図形のどれかが線分の長さ < `ATOL_LEN`、または半径 < `ATOL_LEN` なら、その拘束は
       未充足(`ConstraintUnsatisfied`)。判定は `Slot::admissible` の 1 か所で、試行点の棄却

     - **点が直線上にあるときの `point_line_distance` は `side: Left`・値 0 を返す**(値を符号付き距離の
       絶対値のままにすると、わずかに右側にある点で作った拘束が自分の形を満たさないため)。
     - **拘束が 0 件の文書では走査も組み立てもしない**: 生存数 `live_constraints` を `Document` に持ち、0 なら
       即座に戻る。`NewIds` に `constraints` を足した(新規発行分だけ。消した件数は載せず、app が
       `constraint_count()` の前後差で出す)。

       崩れる形(内接の 2 円が同心・等半径になる等)は通る — 判断3 の退化判定に含める。(b) 拒否された
       `AddConstraint` の `ConstraintUnsatisfied(id)` が指す ID は同じ `apply` の中で墓標になっており、
       `Document::constraint(id)` では引けない。(c) 拘束のある文書では `ModifyEntity` 1 回ごとに全拘束を
       線形に走査する(索引なし。性能は未計測)。(d) **ミラーは側(`Side`)と角度の符号を反転させる**ため、
       接線・点と線の距離・角度のついた図形をミラーすると未充足として拒否される。判断4 の「移動・回転・
       ミラーは自然に扱われる」はミラーについて成り立たない見込みで、タスク97 で扱いを決める
       (采配役の検討で、実機では未確認)。

       新規テストは 70 件。
3. **`Document::apply` の中で解き、拘束は常に満たされた状態を不変条件にする**(タスク97)。
   コマンドを適用した後、変更されたエンティティを含む拘束の連結成分を解き、ほかのエンティティの修正を
   **同じ `HistoryEntry` に入れる**(undo 1 回で全体が戻る。`Command::Batch` の原子性と同じ)。
   解けないときは `Err` を返してコマンド全体をロールバックし、ステータスバーへ出す
   (AGENTS.md「レイヤーロックで失敗しうる操作の `Err` は捨てない」と同じ扱い)。
   - **解くのは最も外側の `Document::apply` 1 回につき 1 回**(2026-09-27 Codex adversarial review
     2回目指摘2 を反映)。`Command::Batch`(入れ子を含む)はサブコマンドを順に**解かずに**適用し、
     その間に (a) 値が変わったパラメータ(適用前と Batch 全体の適用後の差)、(b) 判断4 の規則で消した
     拘束、(c) 追加・値変更した拘束を集める。Batch 全体を適用し終えてから、集めたものに関わる連結成分を
     まとめて 1 回だけ解き、追従した修正を同じ `HistoryEntry` に足す。途中のサブコマンドの失敗も、
     最後の求解の失敗も、Batch 全体のロールバックになる(既存の原子性と同じ)。サブコマンドごとに解くと、
     拘束された複数の図形をまとめて移動・回転したとき、最初の `ModifyEntity` だけを止めた中間状態で
     矛盾して拒否されたり、後続のサブコマンドより前に別の図形が動いて結果が順序に依存したりする。
   - **テスト**(タスク97 の完了条件): 拘束でつながった複数の図形の一括移動・一括回転が受け付けられる
     こと、Batch のサブコマンドの順序を入れ替えても結果が一致すること、Batch の最後の求解が失敗したら
     全サブコマンドが戻ること。
   - **ソルバーが止めておくパラメータ(固定集合)**: (a) 図形の固定の対象(点の固定は方程式なので含まない。判断2)、(b) **ロックされたレイヤー上の
     エンティティの全パラメータ**(ソルバーがロックを破らない)、(c) **そのコマンドで値が変わった
     パラメータ**(利用者が動かしたもの)。(c) により、線分をまるごと移動すれば一致でつながった線分の
     端点が追従し、端点だけをグリップで動かせば同じ線分のもう一方の端点が長さ拘束に従って動く。
   - (c) の結果として、**利用者が動かした図形そのものが拘束に反すれば拒否になる**(例: 水平拘束の
     ついた線分を回転する、固定した図形を移動する)。黙って拘束を外す・黙って形を戻すことはしない。
   - `AddConstraint` は、後に選んだ図形を動かす(ユーザー確定事項)。**最初に選んだ図形のパラメータを
     固定集合へ入れて解き、解けなければ入れずに解き直す**。値の変更(`SetConstraintValue`)は固定集合を
     足さず、最小ノルムで解く。
   - 解いた後の形が退化したら(線分の長さ・半径が退化判定に掛かる、円弧の掃引角が 0 か 2π を超える、
     内接の `s(r1−r2)` が許容値以下)拒否する。
   - **テスト**(タスク97 の完了条件): 求解の失敗(解の無い系・自由なパラメータが無い系・退化・特異点の拒否)の後で、全エンティティ・
     全拘束・undo/redo 履歴・世代番号(`generation`)が適用前と完全に一致すること。
   - **拘束が矛盾する(満たせない)追加は拒否する**。矛盾しない重複(例: 水平の線分に平行な線分へ
     さらに水平)は受け付ける(減衰つきの解法は階数落ちでも解けるため。重複の検出は範囲外)。
   - **拘束が 1 件も無い図面では解かない**(tcad を含め、拘束を使わない利用者の動作と性能を変えない)。
   - **実装時の設計方針追記(2026-10-03、タスク97)**: 求解は `crates/mcad-core/src/document/constraints.rs` の
     `follow_constraints`(`apply` から呼ぶ)と `solve_constraints`(文書の状態と編集内容 → 追従する修正の一覧。
     `apply` から切り離してあり、タスク101 のプレビューが履歴に積まずに使える)。タスク96 の充足検査の足場を
     置き換えた。
     - **連結成分**は拘束を辺・エンティティを頂点として union-find で求め、編集に関わった成分だけを解く。

4. **拘束が指す先の扱いは操作ごとに決める**(タスク96。2026-09-27 Codex adversarial review 指摘2 を
   反映 — 当初案の「エンティティが消えたら消す」だけでは、同じ ID のまま短くなる 1 断片のトリムで
   動いた端点の拘束が残り、ソルバーに拒否されるか別の図形を引きずる)。
   - **着手前に確認した事実(2026-09-27、tool.rs)**: 1 断片のトリムと延長は同じ ID への `ModifyEntity`、
     2 断片のトリムと分割は `RemoveEntity` + `AddEntity` ×2(新しい ID)、フィレット・面取りは
     `ModifyEntity` ×2 + `AddEntity`、結合は `RemoveEntity`(各線分)+ `AddEntity`(ポリライン)。
     移動・回転・ミラー・グリップも `ModifyEntity` なので、**core は `ModifyEntity` を見ただけでは
     「動かした」のか「切り詰めた」のかを区別できない**。
   - **形の切り詰め・延長には新しいコマンド `Command::ReshapeEntity { id, new_geom }` を使う**。
     `ModifyEntity` は「動かす・変形する」の意味に限り、拘束を残してソルバーで満たし直す(判断3)。
     `ReshapeEntity` は次の規則で拘束を**同じ `HistoryEntry` の中で**消してから、判断3 と同じく解く
     (残った拘束は満たされたままのはずなので、普通は何も動かない。満たされていなければ判断3 の
     規則どおり拒否):
     - 位置が変わった点(`Start`・`End`・`Center` のうち、判断1 の長さ型の許容値を超えて動いたもの)を
       指す拘束は消す(一致・点の距離。点の固定は消さずに拒否する — 次項)。
     - 長さに依存する拘束(その線分を含む等長)は消す。
     - 向き・無限直線・半径に依存する拘束(水平・垂直・平行・直交・角度・点と線の距離の「線」側・
       接線・半径・等半径)は残す。切り詰め・延長では直線と円が変わらないため、満たされたままになる。
     - **図形全体の固定、または動いた点の固定がある図形の切り詰め・延長は拒否する**(固定した図形を
       動かす操作と同じ扱い)。
     - 種類が変わり `PointKind` が指せなくなる場合も消す(1 断片のトリムで円が円弧になるとき `Center`
       は残る。逆向きの変化は切り詰めでは起きない)。
   - **操作ごとの対応表**:
     | 操作 | コマンド | 拘束 |
     |---|---|---|
     | 移動・回転・ミラー・グリップ | `ModifyEntity` | 残してソルバーで満たし直す(判断3) |
     | トリム(1 断片)・延長 | `ReshapeEntity` | 上の規則 |
     | フィレット・面取り | `ReshapeEntity` ×2 + `AddEntity` | 上の規則(角の一致は端点が動くので消える)。新しい円弧・線分に拘束は付けない |
     | トリム(2 断片)・分割 | `RemoveEntity` + `AddEntity` ×2 | 元の図形の拘束はすべて消す(新しい断片へは移さない) |
     | 結合 | `RemoveEntity` + `AddEntity`(ポリライン) | 各線分の拘束はすべて消す(ポリラインは対象外) |
     | 削除 | `RemoveEntity` | すべて消す |
   - **消えた拘束は同じ `HistoryEntry` に入り**、undo でエンティティと一緒に戻る。消した件数は
     ステータスバーへ出す(「拘束 n 件を削除」)。
   - 新しい断片へ拘束を移すこと(2 断片のトリム・分割)、フィレット・面取りで接線と一致を自動で付ける
     ことはスコープ外(移し先の決め方と新しい ID の受け渡しの設計が要る。使い込みで要否を判断する)。
   - **複製(`Ctrl+D`)は拘束を複製しない**(範囲外。複製した図形どうしの拘束を写す案は、使い込みで
     要否を判断する)。
   - 移動・回転・ミラーは (c) の固定集合で自然に扱われる(判断3)。
   - **実装時の設計方針追記(2026-10-03、タスク96)**: 削除規則は純関数 `constraint::reshape_removals`
     (変更前後の幾何と拘束の一覧 → 消す ID、または拒否)。`ModifyEntity` と `ReshapeEntity` は履歴記録
     `Applied::ModifyEntity` を共用し、消した拘束を `removed_constraints` に持つ(`RemoveEntity` も同じ)。
     - **「長さに依存する拘束は消す」の改訂**: 等長は、その線分の端点のどちらかが動いたときだけ消す
       (無条件に消すと、形を変えない `ReshapeEntity` でも等長が消えるため。切り詰め・延長では必ず端点が
       動くので、実際の操作での結果は同じ)。
     - 「動いた」の許容値は、変更前後の図形の大きさの最大を `L`、変更前後のその点の座標の絶対値の最大を

     判断3 の「拒否までの時間に上限が無い」への対処(決定的な演算回数の上限と実測の目標値で、強制できる実時間の上限ではない)。`crates/mcad-geom/src/solve.rs`(`Problem::with_work_budget`・
     `solve_metered`・`SolveError::BudgetExceeded`・`rank_work`)、`crates/mcad-core/src/document/constraints.rs`
     (`APPLY_WORK_BUDGET`・`PREVIEW_WORK_BUDGET`・`DOF_WORK_BUDGET`・`DofOutcome`)、`CoreError::ConstraintBudgetExceeded`。
     - **予算は演算回数で数える**(実時間だと同じ入力の結果が機械の負荷で変わり、判断1 の決定性を破る)。単位は
       掛け算 1 回で、`A Aᵀ`(開始時と受理した試行)は `m(m+1)/2 × n`、ガウス消去は実際に消去した行ごとに `n − k`
       (係数が 0 の行は読み飛ばすので数えない。帯行列の連鎖で過大に数えないため)、`Δy`(全試行)は `m × n`。
       ヤコビアン・残差の評価、ピボットの探索、行列の複製、後退代入は省く。**`m × n` は依頼に無い追加**で、棄却の試行にも
       費用がかかること(実測の R の大半)を数えるため。数えてから実行するので、消費は予算を超えない。最初の `A Aᵀ` の分は
       `m × n` の行列を確保する前に数える(Codex adversarial review の指摘 [high]: 確保が先だと、巨大な成分で予算に関わらず
       時間とメモリを使い、メモリ不足で落ちうる)。満たされた系も、ヤコビアンを使わないので確保の前に返す(同レビューの 2 回目の指摘)。
       **実時間の上限ではない**(同 2 回目の指摘 [medium]): 上の省いた処理と系の組み立ては予算チェックの前や合間に動き、
       実時間は機械の状態でも変わる。厳密な上限には求解を UI スレッドの外へ移すか、各段階に中断できる期限チェックが要るが、
       今回は入れていない。
     - **既定は無制限**(`UNLIMITED_WORK`)で、geom の既存の呼び出しと `../tcad` の動作は変わらない。**解き始めで満たされた
       系は予算に関わらず成功する**(唯一の挙動の変更は、開始時に満たされた系でヤコビアンが非有限のときで、`NonFinite` ではなく
       成功を返す。解く必要が無く、評価もしないため)。満たされた成分は core の `settle` が `solve` の前に
       返すので 1 演算も数えず、大きな図面の `.mcad` 読込を予算で落とさない。
     - **予算は最も外側の 1 回の求解全体で共有する**(成分ごと・`solve` ごとではない)。`hold` つきの段階は残りの半分まで
       (打ち切られても残りで `hold` なしの段階を解く)。依頼の「全体の半分」を「その成分を解き始めるときの残りの半分」と
       した: 成分が 1 つなら同じで、複数の成分では `hold` なしの段階の取り分を必ず残せる。減衰の解き直しは停滞・試行上限の
       ときだけ残りの予算で行い、**`BudgetExceeded` は解き直さない**。プレビューと確定は同じ手順を同じ順にたどり、予算だけが
       違うので、プレビューが `Ok` を返した形は確定と bit 単位で一致する(`ModifyEntity` には `hold` が無いので、半分の
       取り決めの差も出ない)。

#### 検収基準(M13完了の定義)

- (i) 線分 4 本で矩形を描き、角を一致、2 辺を水平、2 辺を垂直で拘束すると、1 本の線分を移動したとき
  つながった線分が追従して矩形のまま保たれる。undo 1 回で移動前へ戻る。
- (ii) 距離・半径・角度の値を右パネルで変えると形が変わり、undo 1 回で戻る。
- (iii) 固定した図形を動かす操作、水平拘束のついた線分の回転、矛盾する拘束の追加はいずれも拒否され、
  理由がステータスバーに出て、図面は変わらない。
- (iv) 拘束を付けたとき、最初に選んだ図形は動かず後に選んだ図形が動く(最初の図形を止めたままでは
  満たせない場合を除く)。
- (v) ロックされたレイヤー上の図形はソルバーに動かされない(それを動かさないと満たせない編集は拒否)。
- (vi) 拘束のついた図形を削除・2 断片のトリム・分割・結合すると、その図形の拘束がすべて消える。1 断片の
  トリム・延長・フィレット・面取りでは、動いた端点を指す拘束と等長だけが消え、水平・垂直・平行・半径など
  向きと半径の拘束は残る。いずれも消した件数がステータスバーに出て、undo で図形と拘束がそろって戻る。
  固定した図形の切り詰め・延長は拒否される。
- (vii) 線分の端点、円・円弧の中心と半径、円弧の端点をグリップでドラッグでき、ドラッグ中に拘束の
  追従がプレビューされ、離して確定した操作は undo 1 回で戻る。拘束の無い図面でも使える。
- (viii) 拘束記号の表示を切り替えられ、設定が再起動後も残る。SVG/PDF/DXF に拘束記号は出ない。
- (ix) 拘束のある図面を `.mcad` へ保存して開き直すと拘束がそろって戻る。v1〜v8 の fixture は従来どおり
  読める。DXF へ書き出すと拘束が保存されない旨が出る。
- (x) 右パネルに選択中の図形を含む連結成分の自由度が出て、完全に拘束すると 0 になる。
- (xi) 拘束でつながった複数の図形をまとめて選んで移動・回転でき、拘束は保たれる(undo 1 回で戻る)。
- (xii) 原点から 1e6 mm 離れた位置でも、原点付近と同じ形で拘束の判定(収束・拒否・読込)が変わらない。
- (xiii) 拘束の無い図面での操作・性能が M12 から変わらない(既存テストと性能テストが通る)。
