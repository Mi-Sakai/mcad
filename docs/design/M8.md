### M8: 出力と設定永続化(v0.8.0)の設計(2026-08-01 策定、実装完了)

SVG/PDF エクスポート・線幅/線種の画面反映・設定永続化。着手前の設計入力は
[`M8を始める前に.md`](./M8を始める前に.md)(第6・7章 = 単位系・図面枠・注記基準・GPS 宣言・
規格プロファイル、A-1/A-2 の実測結果)と [`製図規定.md`](./製図規定.md)(第2〜4章 = 用紙・尺度・
表題欄様式・線)。**単位系の確定を含む**ため、当初ロードマップ表の「app 層のみ」から
core/io/geom にも及ぶ構成へ拡大している(2026-08-01)。

#### 設計判断

1. **単位系: 1 ワールド単位 = 1mm と宣言する(内部変換なし)**。既存図面の数値は無変換のまま
   mm として再解釈する(A-1/A-2 のドッグフード図面のみが既存資産であり、ユーザー確認済みの
   前提)。単位は図面メタデータ(判断2)に `unit` として記録する(現状は Millimeter のみの
   `#[non_exhaustive]` enum。inch 等は将来の規格プロファイルで表示・入力側に足す —
   内部単位は変えない)。DXF export は `$INSUNITS = 4`(mm)を書く。

2. **図面メタデータは core の `Document` に置き、変更は `Command::SetSheet` 経由**:
   `SheetMeta { unit, scale: Scale, paper: PaperSize, orientation, title_block: TitleBlockKind,
   fields: TitleBlockFields, frame_visible: bool }`。尺度・用紙・表題欄記入は図面の内容
   (undo 対象)なので Command にする(no-op 判定・undo は `SetLayerProps` と同じ流儀)。
   tcad は本フィールドを使わず壊れない(`tcad-kit` の `SheetMeta` は tcad 側の独自型のまま。
   統合は tcad 側の要求が出た時点で検討し、mcad からは強制しない)。
   - **`Scale { num: u32, den: u32 }`(紙:モデル、既定 1:1)**。中間尺度も整数比で表現できる
     (1:2.5 = 2:5)。換算の定義: `world_mm_per_paper_mm = den / num`(以下 `k` と書く)。
     紙上 x mm の注記はワールド `x * k`。UI は JIS Z 8314 推奨系列(+規定第3章の中間尺度)を
     プリセット提示し、任意比の直接入力も許す(規定 7.2 の決定)。
   - **`Scale` の不変条件: `num > 0 && den > 0`**(Codex M8 設計レビュー(2026-08-01)high 指摘)。
     `num = 0` は `k` が無限大、`den = 0` は注記・線幅・枠がゼロ寸法となり、描画や SVG/PDF 座標へ
     非有限値が伝播する。フィールドは非公開にし、検証済みコンストラクタ
     `Scale::new(num, den) -> Result<Scale, CoreError>` のみで生成する。serde は透過 derive
     ではなく `try_from` 経由(`#[serde(try_from = "…")]`)にして、**手編集された `.mcad` の
     不正値も読込境界で拒否**する。上限(たとえば 10^6)も同時に検証し、`k` の演算が f64 で
     安全な範囲に収める。拒否テストは v4 DTO 読込・`Command::SetSheet`・UI 直接入力の
     3境界それぞれに置く(タスク 35a/35b)。既約化は行わない(2:5 と 4:10 を同一視する必要が
     UI 上なく、表示は入力どおりを保つ)。
   - **紙空間は持たない**(`M8を始める前に.md` 6.1 の決定)。用紙は「モデル空間上の枠」として
     原点 `(0,0)` に用紙左下を置いた矩形で表示する。複数レイアウト・ビューポートは v1.0 後。

3. **図面枠・表題欄はエンティティではなく、メタデータからの派生描画**(グリッドと同格)。
   枠線・表題欄の罫線・欄の文字は毎フレーム `SheetMeta` から生成して描く。編集は
   「欄の値を書き換える = `Command::SetSheet`」であり、図形として選択・移動はできない。
   これが「様式を意味として持つ」(規定 7.2)の実装形。**表題欄テンプレートは宣言的な純データ**
   `TitleBlockTemplate { rows: Vec<Row>, cells: …(セル幅 mm・バインド先フィールド・文字高さ呼び) }`
   として `mcad-core` に置き(serde 可能、tcad の「図枠を自分で作る」ゲーム要素から再利用可能)、
   標準様式 A/B/C(規定 2-4-1)は組み込み定数で提供する。**ユーザー定義様式のデータ構造まで
   実装し、その編集 UI は M8 スコープ外**(標準3様式の選択 + 欄の記入のみ)。
   実装時追加(2026-08-02、タスク35a): `TitleBlockKind::Custom` は `.mcad` に保存される
   ユーザーデータであるため、`SheetMeta::validate()` / `TitleBlockTemplate::validate()`
   (セル幅・段高さの有限・正)と `CoreError::InvalidSheet` を新設し、`Command::SetSheet` の
   適用前に検証する(Scale / WidthMm と同じ境界問題への予防。セル幅合計 = 全体幅までは
   要求せず、標準3様式の合計一致はテストで固定)。

   **実装時追記(2026-08-09、タスク38)**: 図面枠・表題欄の実描画を `mcad-app` に実装した。
   1. **`crates/mcad-app/src/frame.rs` を新設し、紙 mm 座標(原点=用紙左下、y-up)の

      **セル幅を超える長い文字列はクリップせずはみ出したまま描く**(判断7「用紙外の
      図形はクリップしない」と同じ流儀。M8 はクリップ機構を持たない)。
   4. **用紙縁(用紙の外形矩形)は `FrameLayout` に含めず、`draw_paper_edge` という
      別関数で「印刷対象ではない画面専用ヒント」として描く**(グリッドと同じ流儀の
      固定 1px グレー線、`resolve_stroke_px_with_toggle` を介さない)。タスク39 では
      紙自体がページになるため縁線が不要になる、という区別を型・関数の分離として
      今から構造に入れている。表示条件(`sheet.frame_visible`)は `draw_frame` と
      共有し、分岐を1つに保つ(用紙縁だけを別トグルにはしない)。
   5. **UI は右パネルに「図面」セクション(`sheet_panel`)を新設**: 用紙/向き/様式の
      コンボと「図面枠を表示」チェックボックス・尺度(プリセットコンボ+カスタム
      `N:M` 入力+適用ボタン)は、変更のたびに `Command::SetSheet` を1回発行する
      (レイヤーパネルの `SetLayerProps` と同じ「1操作=1undo」の粒度。同値選択は
      core の no-op 判定が吸収する)。表題欄の記入(図面番号・図面名称・投影法・
      作成者・作成日・改訂記号)だけは別モーダル(`egui::Modal`、
      `McadApp::sheet_dialog: Option<TitleBlockDialogState>`)へ分離し、
      作業コピー(`TitleBlockDialogState`)を OK 時に1回だけ `Command::SetSheet` へ
      まとめる(ダイアログセッション全体で undo 1単位。キャンセル/モーダル外
      クリックでは何も適用しない)。`TitleBlockKind::Custom` はコンボの選択肢には
      出さず、選択中表示のみ「ユーザー定義」として出す(A/B/C を選ぶと Custom
      テンプレートは undo 可能な形で置換される。ユーザー確定)。用紙サイズ欄の

      `paper_size_label`)。不正な尺度直接入力(`parse_scale_input` が拒否)は

   6. **モーダルゲートを `McadApp::modal_open(&self) -> bool`
      (`confirm_state != ConfirmState::Idle || sheet_dialog.is_some()`)へ一本化**した。

      入力・ショートカット(undo/redo・ファイル操作・ツール切替・F3/F8/F9/Home)を
      同じ1関数の否定でまとめて抑止する(`app_shortcuts_enabled` の第1引数を

   7. **ズームフィット対象へ枠を考慮**: `frame_visible` が ON のとき、フィット対象
      AABB(`fit_target_aabb`)へワールド `(0,0)〜(用紙幅*k, 用紙高さ*k)` の用紙矩形を

4. **注記(寸法の文字・矢印、Text の高さ)は紙基準 mm へ統一する**(6.2 の決定、A-2 で
   前提条件と確定)。`DIM_TEXT_PX`/`DIM_ARROW_PX`(画面 px 基準)を廃止し、紙 mm 定数
   (寸法文字高さ 3.5(規定第6章の呼び)、矢印長 3.0)× `den/num` のワールド長で描く。
   ズームすると図形と一緒に拡大縮小する(現状の「常に画面14px」から挙動が変わる)。
   Text エンティティの `height` は保存値の解釈を「ワールド単位」から「紙 mm」へ変え、
   ワールド高さは `height * den / num` で導出する。既定尺度 1:1 では数値も見た目も
   不変なので、v3 図面の移行は解釈変更のみで済む(判断6)。
   **寸法スタイルの中身(文字位置規則・補助線すきま・外向き矢印・桁数/公差)は M8 では
   触らない** — A-1 で確定したとおり G2「寸法の GPS 化」で寸法スタイルとして一括設計する。

   **実装時追記(2026-08-09、タスク37)**: タスク36b で導入した「線幅表示」トグルを
   「紙基準表示」トグル(`McadApp::paper_display_enabled`。旧
   `lineweight_display_enabled`。UI ラベルは上部パネルが英語領域のため
   `"Lineweight:"` → `"Paper view:"`)へ拡張し、寸法注記(文字・矢印)も対象にした
   (手動スモークテスト時のユーザー判断、判断5 実装時追記(タスク36b)の末尾を参照)。
   実装で確定した点:
   1. **`dim_sizes` は `(paper_display: bool, k: f64, zoom: f64) -> (arrow_len, text_height)`
      の3引数形にした**(タスク表の `dim_sizes(scale)` 案から変更)。トグル導入前は
      「紙 mm 基準か画面固定 px 基準か」の分岐が存在しなかったため単一の尺度引数で
      足りたが、36b のトグルにより OFF/ON の2経路を1関数に集約する必要が生じた。
      OFF は `DIM_ARROW_PX`/`DIM_TEXT_PX`(画面固定 px)÷ `zoom`、ON は
      `DIM_ARROW_MM`/`DIM_TEXT_MM`(紙 mm 定数)× `k`。
      **記述の訂正(2026-09-05、タスク54)**: この2定数はタスク37 時点の実装であり、
      M9 タスク49-3 で削除された。現在の `dim_sizes` は `DimStyle` を引数に取り、ON は
      `style.arrow_len_mm`/`style.text_height_mm`(スタイルの紙 mm 値)× `k` を返す
      (詳細は `docs/design/M9.md` 判断4 の記述の訂正、および `dim_sizes` の doc コメントを参照)。
   2. **`DIM_ARROW_PX`/`DIM_TEXT_PX` は廃止せず、「紙基準表示 OFF 時の画面固定 px」
      専用定数として存続させた**。既存の undo/redo・出力(タスク39/40)に影響しない
      表示のみの後方互換であり、値そのものは 36b 以前と同じ意味を保つため、
      別名へ置き換えるより「OFF 時専用」と doc で明示するほうが差分が小さく読みやすい。
   3. **Text エンティティはこのトグルの影響を受けず、常に `height * k` で表示する**
      (ユーザー確定)。理由: (a) Text の選択ハイライト用 AABB・矩形選択の内包判定
      (`SelectTool::pick`/`on_drag_end`)・zoom fit(`document_aabb`)は、判断4 が
      定めた「`height` は紙 mm」というデータ意味論に従うのが筋であり、表示 ON/OFF で
      選択可能範囲が変わると直感に反する。(b) 1:1(既定尺度)では `k=1` なので
      トグルの有無に関わらず従来と完全に同一の見た目・挙動になり、回帰リスクがない。
      (c) タスク39/40 の SVG/PDF 出力は尺度を必ず反映するため、Text だけ表示を
      トグルで往復できるようにしても出力との整合確認という当初の目的を満たさない。
   4. **`text_world_aabb(text, k)` は `mcad-core` の `EntityGeom::aabb()`(1:1 解釈)を
      anchor 基準に `k` 倍する相似拡大として実装した**(`mcad-app` 側の純関数、
      `mcad-core::text_aabb` はテスト以外から見えない非公開関数のため直接は使えない)。
      これが「height×k の TextGeom の aabb()」と厳密に一致する根拠: `text_aabb` が
      組む局所4隅は anchor を原点として `width`・`height` に**線形**に比例するベクトルを
      ベースライン角で回転したものであり(`width` 自体も文字数 × 係数 × `height` で
      `height` に線形)、`height` を `height*k` に置き換えると4隅は
      `anchor + k*(corner − anchor)` へ写る。`k > 0`(`Scale` の値域は正)なので
      この写像は各軸で単調であり、4隅の外接矩形(min/max)も同じ写像で移る。
      ゆえに「元 AABB を anchor 基準に `k` 倍」と「height×k の TextGeom の aabb()」は
      同じ結果になる。`mcad-core::EntityGeom::aabb()` 自体は tcad の path 依存があるため
      シグネチャ・実装とも変更せず、doc コメント追記のみ行った。
   5. **`draw_text` はワールド高さ `world_height: f64` を明示引数で受ける形へ変えた**
      (二重換算防止)。呼び出し側は2系統に分かれる: Text エンティティ・プレビュー・
      ゴースト・選択ハイライトは `text.height * k` を渡す(上記3)。一方
      `draw_dim_expansion` は `dimension::expand_linear`/`expand_radial` が
      `dim_sizes` の戻り値(既にワールド長)から組み立てた `ex.text.height` を
      **そのまま**渡す — ここでさらに `k` を掛けると二重換算になる(展開時点で
      ワールド長への変換が完了しているため)。旧実装は `draw_text` が内部で
      `text.height * viewport.zoom` を計算していたため、この区別が暗黙のうちに
      `TextGeom.height` の意味(常にワールド高さ)へ依存しており、判断4 の解釈変更後は
      Text エンティティ用に `k` 倍が要る一方、寸法展開は不要という非対称が生まれた。
      これを呼び出し側の責務として明示引数化することで、今後同様の非対称が増えても
      二重換算に気づきやすくした。

   **手動スモークテスト(2026-08-09、ユーザー実施): 問題なし**。確認項目は
   (1) F9 で `Paper view: OFF`/`ON` が切り替わる、(2) 既定 OFF の見た目が
   タスク36b 以前と同一(全線 1px・寸法注記は画面固定 px)、(3) ON で線幅が反映され
   寸法矢印・数値が図形と一緒に拡縮する、(4) 寸法プレビューが確定後と同じサイズ規則、
   (5) Text プレビューと確定後の一致・選択枠が文字に沿う、(6) ラベル変更による
   上部パネルのレイアウト崩れがない、の6点。尺度 1:2 での目視確認は尺度変更 UI が
   タスク38 のため**タスク38 の手動スモークへ繰り延べ**た(`k != 1` のロジック自体は
   `dim_sizes`・`text_world_aabb`・`document_aabb`・`SelectTool::pick` の単体テストで
   固定済み)。Codex レビュー(`/codex:review`、2026-08-09)は指摘ゼロ。

4a. **換算表(格納値 → 各出力先)**(Codex M8 設計レビュー(2026-08-01)の提案による追加。
   `k = den / num` = 紙 1mm あたりのワールド mm。例: 1:2 → k=2、2:1 → k=0.5):

   | 量(格納形) | 画面(px) | DXF(モデル単位 = mm) | SVG/PDF(紙 mm) |
   |---|---|---|---|
   | Text 高さ `h`(紙 mm) | `h * k * zoom` | **`h * k`**(1:2 で 3.5 → 7.0) | `h` |
   | 寸法文字 3.5 / 矢印 3.0(紙 mm 定数) | `* k * zoom` | —(寸法は DXF 非出力) | そのまま |
   | 線幅 `w`(紙 mm) | `max(1px, w * k * zoom)` | lineweight として `w` 直接(尺度非依存の表示属性。可否は 35c で実測) | `w`(クランプなし) |
   | 破線パターン長(紙 mm 定数) | `* k * zoom` | LTYPE 定義値の扱いは 35c で実測後に決定 | そのまま |
   | 用紙・枠・表題欄(紙 mm) | `* k * zoom` | —(非出力) | そのまま |
   | モデル図形の座標(ワールド mm) | `* zoom` | そのまま | `/ k` |

   - **DXF TEXT 高さの契約**(Codex high 指摘への回答): DXF の TEXT 高さはモデル空間の長さ
     なので、export は **`h * k` を書く**(現行の無変換転写は 1:1 でのみ偶然正しい)。
     import は DXF に図面尺度の概念がないため **1:1 とみなして取り込む**(高さの数値を
     そのまま紙 mm とする)。この結果、尺度付き図面の export → import では「紙 mm の意味」は
     往復しない(モデル空間での幾何サイズは正しく保存される)。これはレイヤー重ね順と同種の
     「仕様として非保存」であり、AGENTS.md へ記録する。**実装の担当はタスク 35c(io 層)**で、
     1:2 での export 値(3.5 → 7.0)と往復の幾何サイズ不変をテストで固定する。

5. **線幅・線種は「レイヤー既定 + エンティティ上書き」(ByLayer)モデル**:
   - `Linetype` enum(`Continuous` / `Dashed` / `DashDot` / `DashDotDot`、`#[non_exhaustive]`)を
     core に新設。破線パターンの実長は**紙 mm 基準**(尺度に追従)で app 層の定数に置く。
   - `Layer` に `linetype: Linetype` と `width_mm: WidthMm` を追加(規定 4-1 の「実線_中 0.35mm」等の
     線名称 = レイヤー運用を想定。標準レイヤー構成は規定側の残タスク)。
   - `Style` は `width: f32`(現状 px、実質未使用)を `width_mm: Option<WidthMm>`(None = ByLayer)に
     置き換え、`linetype: Option<Linetype>`(None = ByLayer)を追加。
   - **`WidthMm` は検証済み型**(Codex M8 設計レビュー2周目(2026-08-02)high 指摘。`Scale` と
     同じ境界問題が線幅にもある): 有限・正・範囲 `0.05..=5.0 mm`(ISO 128 系列 0.13〜2.0 を内包し、
     DXF lineweight の最大 2.11mm も収まる)を `WidthMm::new(f32) -> Result<WidthMm, CoreError>` と

     しか到達しない(画面側の 1px クランプが不正値を隠す事故を境界で断つ)。

6. **`.mcad` v4**: 判断2(SheetMeta)・判断5(Layer/Style 拡張)・判断4(height の解釈変更)を
   **1回のバージョン上げにまとめる**。v1〜v3 読込は既存の凍結 DTO 方式を踏襲し、
   `sheet = 既定(A4 横・1:1・様式B・frame_visible=false)`、`Layer` は
   `linetype=Continuous, width_mm=0.35`。
   - **旧 `Style.width`(px)は「破棄」ではなく、旧実装の実効表示幅を保存する決定的換算で
     移行する**(Codex M8 設計レビュー2〜4周目(2026-08-02)指摘への回答。旧フィールドは
     public かつ serialize されており任意値の v3 ファイルが合法 — フィクスチャにも 2.5 が実在。
     旧描画は `max(width_px, 1.0)` px・ズーム非依存だったので、**保存すべきは生の格納値では
     なくこの実効表示幅**である):
     1. **入力領域は有限の f32 のみ**: `.mcad` は serde_json であり、JSON は `NaN`/`Infinity` を
        表現できないため非有限値を含むファイルはパースエラーになる(4周目 medium 指摘への
        回答: `+∞` は旧描画でも 1px にならない(`max` は `+∞` を返す)が、そもそも到達不能。
        この事実は 35b で `Infinity` 入り v3 JSON の読込拒否テストとして固定し、移行規則の
        入力領域から除外する)
     2. `width_px == 1.0`(シリアライザが書く既定値。UI から設定不能なため「未指定」とみなす)
        → `width_mm = None`(ByLayer 0.35mm)。**明示値の ByLayer 化は意味変更**(後から
        レイヤー幅を変えるとこれらのエンティティが追従する)だが、未指定の既定値については
        ByLayer 追従こそが意図した意味付けである。このため意味の等価の保証は
        「読込直後・レイヤー幅未変更時」に限定する(4周目 high 指摘への回答)
     3. `width_px != 1.0`(手編集等による明示値)→ `width_mm = Some(0.35mm × max(width_px, 1.0))`
        (**ByLayer 化しない**。レイヤー編集の影響を受けない「エンティティ固有値」という旧の
        意味を保存する)。実効 `> 5.0/0.35(≈ 14.286)` px は上限 5.0mm へクランプし、黙殺せず
        読込サマリに件数計上してステータスバーへ表示する(DXF import の skipped 計上と同じ流儀)
     テスト(35b)は7ケース: `1.0 → None` / `2.5 → Some(0.875)` / `0.5 → Some(0.35)`・
     `-3.0 → Some(0.35)`(実効表示幅 1px の保存)/ `5.0/0.35 → Some(5.0)`(クランプ・計上
     なし)/ `20.0 → Some(5.0)` +計上 / `Infinity` 入り JSON → パースエラー。
   - **移行の保証は「実効表示幅(`max(width_px, 1.0)` px)の×0.35mm 換算による保存 + 上限
     クランプのみ例外(警告つき)」であって、生の格納値の保存でも任意ズームでの描画同一でも
     ない**(1〜4周目で段階的に精密化): `zoom = 1/0.35 ≈ 2.857`(丸めず定数 `1.0 / 0.35` で
     扱う)において、クランプされない全エンティティの画面幅が旧実装と厳密一致する。
     規則2(ByLayer 化)のエンティティはさらに「レイヤー幅が既定 0.35mm のまま」という条件
     つきで `zoom <= 1/0.35` の全域一致(レイヤー幅を編集すれば追従して変わる — ByLayer の
     意図どおりの挙動)。規則3の明示値はレイヤー編集の影響を受けない。上限クランプは明示的な
     警告つきの互換性劣化として受け入れる(紙上 5mm ≒ 実効 14px 超の線幅は製図上の意味を
     持たない)。高ズームで太くなるのは**線幅の画面反映という M8 の目的そのもの**であり、
     互換表示規則で旧図面だけ px 固定にする価値はない(描画規則の分岐とテスト・出力の二重化を
     招く)。意図した可視差として CHANGELOG に明記する。
     検収: (a) v3 → v4 読込でエンティティ・レイヤー・Text 値が無損失で、上記7ケースが規則
     どおり(単体テスト)、(b) 線幅解決がクランプ対象外の全ケースで `zoom = 1/0.35` において
     旧式 `max(width_px, 1.0)` と一致し、規則2はレイヤー幅既定のまま `zoom <= 1/0.35` 全域で
     一致(単体テスト、閾値は定数 `1.0 / 0.35`)、(c) 高ズームで太くなること・クランプ警告
     表示の手動スモークテスト確認、の3点に**限定して**行う。

7. **SVG/PDF 出力は mcad-app 内の egui 非依存モジュール(`plot`)に置く**。理由: 文字を
   紙に出すにはフォント(Noto Sans JP)のメトリクスとアウトラインが必要で、フォントは app 層に
   ある(M6 の justified TEXT skip と同じ依存方向の制約。io 層に置くとフォントを io へ下ろす
   ことになり逆流する)。mcad-io は `.mcad`/DXF 専任のまま。
   - **中間表現を挟む**: `plot::PlotPage`(紙 mm 座標のポリライン列・円弧・塗り・文字アウトライン
     パス列)を生成する純関数群(単体テスト可能)+ それを SVG / PDF へ直列化する2つの
     バックエンド。座標変換(ワールド→紙 mm、y 反転)・線幅・破線・注記サイズの解決は
     中間表現の生成側で1回だけ行い、バックエンドは幾何を書くだけにする。
   - **文字はアウトラインパスへ変換して出力する**(`ttf-parser` でグリフ輪郭を取得、advance で
     単純送り。カーニングなし — egui の表示と厳密一致はさせない)。フォント埋め込み
     (サブセット化)を回避でき、CJK が閲覧環境に依存せず確実に出る。「記号はジオメトリ生成」
     (G0-⑤)と同じ思想。SVG の `<text>` 併記(検索性)は将来オプション。
   - **PDF は `pdf-writer` クレート**(低レベル・依存最小。アウトラインパス出力なら
     フォント機能が不要なため高レベルな printpdf を要しない)。SVG は手書き XML(依存追加なし)。
   - 出力範囲は用紙矩形(判断2)。用紙外の図形は**クリップせずそのまま描く**(はみ出しは
     作図者の責任とし、M8 ではクリップ実装を持たない。ビューアの表示範囲外に出るだけ)。

   **実装時追記(2026-08-11、タスク39)**: 構成は `crates/mcad-app/src/plot/` に
   `mod.rs`(IR + `plot_page` builder + 円弧のベジエ化 + 紙 mm 定数)・`text_outline.rs`
   (`ttf-parser` によるグリフアウトライン化)・`svg.rs`(手書き XML の直列化)の3分割で確定。
   `egui::` 参照ゼロを grep で確認済み。`ttf-parser = "0.25"` を `mcad-app` へ追加したが、
   依存グラフに既に 0.25.1 が入っており(winit → sctk-adwaita → ab_glyph →
   owned_ttf_parser → ttf-parser)`Cargo.lock` 上も1本に dedup された。フォントは
   `fonts.rs` に `embedded_font_bytes()` を足して画面と共有(ttf-parser の CFF 対応は
   feature flag 不要のコア機能)。紙 mm 基準の破線パターン・寸法文字/矢先サイズの定数も
   `plot` へ集約し、画面側の `dash_pattern_px` / `dim_sizes` はここを参照するだけにした
   (挙動不変)。
   - **IR は当初想定の「ポリライン列・円弧・塗り・文字アウトラインパス列」から**
     `PlotPath` 1種への統一へ寄せて確定した: `PlotPage { width_mm, height_mm, paths }` /
     `PlotPath { cmds, stroke, fill }` / `PathCmd::{MoveTo, LineTo, CurveTo, Close}`。
     線分・ポリライン・円・円弧・矢先・文字をすべて同じ型で表す。SVG のネイティブ弧
     (`A`)は使わない — PDF にネイティブ弧が無く、SVG だけ使うとタスク40 の「同一の
     中間表現を使い分岐しない」に反するため。`QuadTo` は持たず、TrueType 由来の2次
     曲線は厳密な次数上げで3次化する(CFF は元々3次)。
   - **座標系は紙 mm・原点=用紙左下・y-up**(`FrameLayout`・ワールドと同一)で確定。
     y 反転は SVG 直列化の1箇所のみで行い、PDF(タスク40)は元来 y-up なので反転なしで
     素通しできる — IR を y-down にすると PDF 側で逆反転が要って損をするため。
   - **円・円弧のベジエ近似は 90° 分割**で確定。最大半径誤差は実測 `2.73e-4 × r`
     (画面の `ARC_SEGMENTS = 64` ポリライン近似のサジッタ誤差 `1.20e-3 × r` より
     4.4 倍高精度)。絶対値が 0.01mm を下回るのは紙 r ≤ 36.7mm まで、A4 いっぱいの
     大円(紙 r = 100mm)でも 0.027mm(最細線幅 0.13mm の 1/5)で目視できず、寸法値は
     数値として別出力されるため計測精度へは波及しない。45° 分割なら `4e-6 × r` まで
     落ちるがパスデータが倍になるだけなので 90° 分割で確定。
   - **換算は builder で1回だけ**: モデル座標は `÷ k`、`TextGeom::height`(紙 mm)は
     無換算、`DimExpansion` の座標・長さ・文字高さ(ワールド長)は `÷ k`、線幅
     `WidthMm` と破線パターンと `FrameLayout` は無換算。**F9(紙基準表示)は出力に
     一切影響しない**(実機で ON/OFF 双方から出力した SVG が `diff` でバイト一致)。
     出力側は線幅の下限クランプをしない(判断5 のとおり 0.05mm がそのまま出る)。
     カリングもクリップもしない。ダッシュの位相はパス先頭から 0 固定(画面はクリップ
     区間ごとに位相をリセットする既知の近似なので、出力の方がむしろ正確)。
   - **色は純白 (255,255,255) のみ黒へ再マップ**し、他の色は素通しする(ユーザー判断)。
     既定レイヤー `"0"` の色が `Rgb::WHITE` のため、無対策だと白紙に白線で不可視になる。
     AutoCAD の ACI 7(white/black 双対)と同じ慣行で、mcad の DXF export も白は
     ACI 7 へ落ちるので整合する。枠・表題欄は黒(画面の `FRAME_COLOR` gray150 は
     暗背景向けの表示色であって印刷色ではない)。
