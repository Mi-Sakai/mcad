### M9: 寸法のGPS化(v0.9.0)の設計(2026-08-12 策定、design-fable案をユーザー承認のうえ確定、実装完了)

`M8を始める前に.md` 6.3節の段階表における **G2「寸法のGPS化」の実行**。寸法補助記号(φ・Sφ・□等)と
サイズ公差(JIS B 0420 / ISO 14405 系)を寸法に載せ、寸法スタイルを導入する。G2 は策定時点(2026-08-01)
から「M8 直後、M9(旧番号。DXF DIMENSION import)より前」という順序制約つきで構想されていたため、
M8 完了(2026-08-11)を受けてそのまま M9 として起こした(旧 M9 は M10 へ、旧 M10 は M11 へスライド。
マイルストーン一覧表を参照。2026-08-18 の M10「表・部品表」挿入で再スライドし、旧 M9 の内容は
現在 M11、拘束ソルバーは M12)。A-1 痛点の「寸法スタイル系4件」(桁数/記号/公差の設定窓・補助線すきま・
文字位置後編集・矢印の外向き配置)はいずれも本マイルストーンの範囲に収まると仕分け済み。

設計はdesign-fableへ委譲し、采配役の一次レビュー後、以下の可視差・スコープ追加・実施順序を
ユーザー承認済み(2026-08-12)。

#### 設計判断

1. **記号セットと表現方式**: 記号の意味は `mcad-geom` 新モジュール `symbol` の `#[non_exhaustive]`
   enum `DimSymbol`(Diameter(φ)/SphereDiameter(Sφ)/Square(□)/Radius(R)/SphereRadius(SR)/
   ControlRadius(CR)/Chamfer(C)/Thickness(t))で持つ。**ジオメトリ生成するのは φ・□ の2字のみ**
   (G0-⑤ の決定どおりフォントに頼らない)。R・S・C・t 等の英字は値文字列と
   同じフォント文字として組版する(Sφ = フォント"S" + 生成φ)。生成関数
   `dim_symbol_glyph(sym, h) -> SymbolGlyph { shapes: Vec<Shape>, advance: f64 }` は
   ローカル座標(原点=ベースライン左端・高さh)の純関数として `mcad-geom` に置く(依存方向上、
   core の永続化フィールドから参照できるのは geom 側のみ)。UI ウィジェットのラベルは
   フォント文字の "φ" 等を使ってよい(G0-⑤ が縛るのは図面描画と出力のみ)。比率定数(暫定:
   φ=円0.7h径+約65°斜線、□=0.7h角)はタスク45 の規定例図と目視整合させて確定する。
   弧長記号(⌒)は弧長寸法エンティティ自体が未実装のため見送り(non-goal)。
2. **公差データモデル**: `mcad-core` に `DimAnnotation`(symbol・tolerance・
   decimals_override(下記の桁数継承モデル)・value_override(非比例寸法、規定5-10)・
   text_anchor(文字位置後編集)・arrow_placement)と `SizeTolerance`(`#[non_exhaustive]`:
   Symmetric(±v)/Deviations{upper,lower}/Fit(FitClass、"H7"等の検証済み文字列)) を新設し、
   `DimLinear`/`DimRadial`/`DimDiameter` へ埋め込む。全フィールドに既定値があり、既定は
   現行描画と同値(無注記)。種別ごとの許容記号(Linear: φ/Sφ/□/C/t、Radial: R/SR/CR、
   Diameter: φ/Sφ)の文法検証を `DimAnnotation::validate(kind)` で行い、**core コマンド境界・
   v5 読込・UI 入力の3境界すべてで不正組合せ・`upper < lower`・非有限・不正 Fit 文字列を
   拒否する**(M8 の Scale/WidthMm と同じ流儀)。**はめあい記号は表示のみ**(ISO 286 表の内蔵・
   偏差値自動換算は non-goal)。公差解析(スタックアップ)・実測データ評価・完全 MBD は G0 で
   確定済みの non-goal のまま変更しない。
   - **実装時追記(2026-08-12、Codex adversarial review 反映、High)**: 当初案は
     `envelope: bool`(Ⓔ)を `DimAnnotation` の独立フィールドとして持たせていたが、寸法は
     非関連(図形追従なし)でサイズ形体(feature of size)との対応づけを持たないため、
     core が「この寸法にⒺを付けてよいか」を判定できず、任意の点間寸法・半径寸法へ
     Ⓔを付けて保存できてしまう欠陥がある(規格に則って見えるが意味的に不正なデータが
     作れる。tcad の検図入力としての構造化GPS仕様という狙いを損なう)。
     **対応: Ⓔ(および ISO 14405 系のその他修飾子)は M9 では実装しない**(non-goal 側へ移動、
     下記10)。feature-of-size の意味論的分類・対応づけができるまで、修飾子は「サイズ公差の
     値そのもの」(判断2本文)に限定する。修飾子の実装は G3(データム等で feature-of-size の
     扱いが必要になる段階)以降で、対応づけの設計とあわせて再検討する。
3. **直径寸法 `DimDiameter` を新設する**(スコープ追加、ユーザー承認済み、2026-08-12)。
   理由: (a) φ記号だけ追加すると「円に半径寸法+φ上書き」という意味的に誤った運用
   (R12 と φ24 の取り違え)を誘発する、(b) 円の直径寸法を入れたいという既知ギャップを閉じる、
   (c) `.mcad` v5 のバージョン上げに相乗りでき、単独で後回しにすると v6 が別途必要になる。
   データは `DimDiameter { center, radius, angle, annotation }`(寸法線は中心を通る angle 方向、
   矢は円周2点)。角度寸法・弧長寸法・座標寸法は見送り(non-goal、M11以降)。
4. **寸法スタイルは文書単位の単一 `DimStyle`**(名前付き複数スタイルは non-goal)。
   `Document.dim_style` + `Command::SetDimStyle`(no-op判定・undo、`SetSheet` と同じ流儀)。
   フィールド: `text_height_mm`(既定3.5)・`arrow_len_mm`(3.0)・`decimals`(2)・
   `trim_trailing_zeros`(既定 true)・`ext_gap_mm`(補助線すきま、暫定1.0)・
   `ext_overshoot_mm`(補助線突き出し、暫定2.0)・`text_gap_mm`・`tolerance_scale`(上下偏差の
   縮小率、暫定0.7)。既定値の最終確定はタスク45(規定5-4)と連動。`SheetMeta` へは入れない
   (用紙の関心事ではなく作図内容のスタイルのため)。
   **記述の訂正(2026-09-05、タスク54)**: 当初は「現行の `plot::DIM_TEXT_MM`/`DIM_ARROW_MM`
   定数はスタイル既定値の供給元へ役割変更」としていたが、タスク49-3 の実装は役割変更では
   なく**両定数を削除**し、`DimStyle::DEFAULT` を実際の描画サイズの唯一の出所にした
   (描かれる大きさを app 層の定数、矢の内外判定と組版の比率を `DimStyle`、と二重に持つと
   タスク50 のスタイル編集 UI で破綻するため。詳細は `crates/mcad-app/src/main.rs` の
   `dim_sizes` の doc コメントを参照)。
   - **実装時追記(2026-08-12、Codex adversarial review 反映、Medium)**: 当初案は
     `DimAnnotation.decimals`(エンティティ側)と `DimStyle.decimals`(文書側)を並存させて
     いたが、エンティティ側の値が「明示上書き」なのか「読込時のスナップショット」なのか
     「常に文書側優先」なのか未定義だった。v4 読込時に具体値を埋めてしまうと、後から
     `SetDimStyle` で桁数を変えても反映されない寸法が生じる/または逆にエンティティ側の
     手動指定が無効化される、というどちらに転んでも実装後の再移行(v6)を招く不整合がある。
     **対応: `DimAnnotation` 側は `decimals_override: Option<u8>` に改める**。`None`(既定、
     v1〜v4 からの移行値もこれ)は「文書の `DimStyle.decimals` に従う(生きた参照であり、
     `SetDimStyle` の変更が即座に反映される)」ことを意味し、`Some(n)` はそのエンティティに
     限った明示上書きとする。UI には「スタイルに戻す」操作(`Some → None`)を設ける。
     この優先順位・移行規則・UI 挙動・境界値検証をタスク47・48・50 の完了条件に明記する
     (下記タスク分割・検収基準に反映済み)。
   - **実装時追記(2026-09-04、タスク45 の JISC 照合結果、ユーザー確定)**: 既定値と規格の
     突き合わせを完了した。`ext_gap_mm` 1.0 / `ext_overshoot_mm` 2.0 は JIS B 0001:2019
     11.2 b) に数値の定めがなく(「僅かに離してもよい」「僅かに超えるまで延長する」)、
     **本規定の独自値として確定**(JIS Z 8317-1:2008 5.4 の「寸法補助線の太さの約8倍」は
     採らない。ユーザー判断)。矢印の開き角度 20° は JIS Z 8317-1 附属書A(30°・90°)に無く
     独自値(7章「寸法矢印のブロック化」に記録)。`text_height_mm` 3.5 は今回の照合対象外。
     したがって**規格値と実装値の食い違いによる新タスクは発生しない**。出典コメントは
     `製図規定.md` 4-1 / 5-2 / 5-3 / 5-4 に反映済み(未公開ファイルのため差分はリポジトリに出ない)。
5. **JIS 配置規則への変更(可視差3点、ユーザー承認済み・2026-08-12)**: (a) 寸法数値のゼロトリム
   既定 ON(`120.00` → `120`)、(b) 寸法文字を常に寸法線の**上側**へ配置(JIS Z 8317 の読み取り
   方向規則。現行「計測対象から遠い側」から変更)、(c) 寸法補助線にすきま・突き出しを追加。
   いずれも保存データ不変・描画のみの変化であり、**M8 判断6(高ズーム時の線幅可視差)の前例
   どおり旧挙動の互換表示規則は作らず、CHANGELOG に可視差として明記する**。外向き矢印は
   「文字幅+矢2つが寸法線長に収まらなければ外向き」の自動判定+ `arrow_placement` の手動上書き。
6. **`.mcad` v5**: `DimAnnotation`・`DimDiameter`・`dim_style` を1回のバージョン上げにまとめる。
   v4 以前は既定値補完(annotation 既定・dim_style 既定)で無損失。v4 DTO は凍結する。
7. **文字位置ドラッグは既存 pick 契約を壊さない**: `text_anchor` の編集は「選択済み寸法の
   文字ブロック(展開結果の表示サイズ依存 AABB)をドラッグ開始点で判定」する SelectTool 内の
   別経路とし、`linear_pick_segments` 等のズーム非依存 pick 契約(`dimension.rs` 冒頭 doc)は
   変更しない。「自動配置に戻す」操作を右パネルに置く。
8. **引出線は独立エンティティとする決定のみ本マイルストーンで行い、実装は G3 へ回す**
   (ユーザー承認済み、2026-08-12)。根拠: G2(寸法補助記号・公差)は引出線を使わないため、
   決定だけで足りる。G3(データム・表面性状・溶接記号)は引出線を前提とするため、そちらで
   データ構造(`Leader { points: Vec<Point2>, .. }` 案)を確定する。`DimRadial.leader_angle`
   の埋め込みは現状維持(Leader 実装時に再検討)。
9. **`DimSymbol` enum を `mcad-geom` に置く**ことの確認(ユーザー承認済み、2026-08-12)。
   geom に永続化 serde 型が増える初めてのケースだが、tcad への影響は additive のみ
   (`EntityGeom` の `#[non_exhaustive]` により tcad 側の網羅 match は影響を受けない)。
10. **non-goal(明記)**: 公差解析(スタックアップ)・実測データ評価・完全 MBD /
    **Ⓔ等の ISO 14405 系修飾子(feature-of-size 対応づけができるまで見送り。判断2実装時追記
    参照)** / 幾何公差記入枠・データム・表面性状・溶接記号・引出線の実装(いずれも G3) /
    角度・弧長・座標寸法・穴指示記号(引出線前提のため G3) / 関連寸法(図形変更への追従) /
    名前付き複数寸法スタイル / ISO 286 はめあい表の内蔵(偏差値自動換算) / 一般公差の
    `SheetMeta` フィールド・注記自動生成(規定側に記入位置の定めがなく様式規定の改定が先。
    Text で手書き可能) / DXF DIMENSION(M11、G2 モデルへの写像として一括設計する) /
    出力モノクロ化のレイヤー別オーバーライド(下記11、v0.8.x 側の non-goal)。
11. **小粒課題(随時対応)の配置**: データ・規定に触れないもの(**出力モノクロ化**・分割ツールの
    スナップ対応・ズーム/パンの追加操作手段)は本マイルストーンより先に **v0.8.x の番号外
    リリースで消化する**(出力モノクロ化は設計・タスク分割まで本章「随時対応」の当該項目で確定済み、2026-08-12)。
    core/規定に絡むもの(**エンティティのレイヤー変更コマンド**・**標準レイヤー構成と文字/寸法の
    自動レイヤー割当**)は本マイルストーン内(タスク52・53)に含める。
